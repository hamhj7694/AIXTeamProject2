# MVP_v2 PRD 요약

의심 통화를 문장별 ML과 전체 맥락으로 분석하고, 임계값 이상이면 하나의 Case를 생성한다. 고객·은행·검증 담당자·AI가 같은 Case를 역할별 공개 범위에서 상담·질문·검증·보호조치·보고로 이어간다. 탐지 정확도보다 탐지 이후의 정보수집·사건맥락 재구성·고객 설득·업무 인수인계를 하나의 Case에서 연결하는 것을 핵심 가치로 둔다.

최종 화면은 Case 목록, Case 개요, 고객 상담, 은행 대응, 기관 검증이다. 고객은 진행 스테퍼·상태별 안전/피해구제 안내·질문 카드를 보고, 은행은 내부 협업·고객 대화·AI 개인 작업공간과 사건 진행 타임라인을 사용한다. 고객이 `이미 사기 당했어요`를 선택하면 화면 구조는 유지하고 오른쪽 `안전 상담 안내`만 `보이스피싱 피해 구제 안내`로 교체한다. AI 제안은 사람 승인 전까지 후보이며 외부 기관·금융거래를 자동 실행하지 않는다.

고객 상담 화면의 정본은 `/cases/{case_id}/customer`에서 렌더링하는 `CustomerChatPage + features/mvp-chat` 하나뿐이다. PREVENT와 RECOVERY를 별도 페이지로 만들지 않고 동일 URL과 Chat-first Shell에서 서버 Case 상태에 따라 전환한다. 고객 화면에는 목록용 내부 Case 컬럼과 중복 진행 스테퍼를 노출하지 않고, 상단 안전 경고·피해 신고 전환·채팅·오른쪽 고객 진행 카드만 유지한다.

고객 상담의 데스크톱 레이아웃은 모든 상태에서 `왼쪽: 채팅 / 오른쪽: 현재 진행 상황과 안전·피해구제 안내` 순서를 고정한다. 피해구제 모드 전환이나 카드 생성이 Grid 열 순서를 변경해서는 안 된다.

## Chat-first 원칙

채팅은 단순 상담창이 아니라 조회·질문·검증·Fact·조치·상태변경·공유가 시작되는 기본 작업 인터페이스다. 다만 Case 목록, Timeline, 진행 스테퍼, 개인 메모, 북마크, 보고서는 계속 확인해야 하는 보조 UI로 제공한다. 모든 상호작용은 Message, Question, CaseFact, Verification, BankAction, Bookmark, PersonalNote, Event 같은 구조화 객체로 저장한다.

## 신규 필수 기능

- 은행 담당자의 Case별 개인 메모: 작성자 본인만 보는 자동저장 메모이며 필요할 때만 내부 공유 또는 Fact 후보로 전환한다.
- 메시지/카드 북마크: Case별 바로가기 목록에서 원본 채널·메시지로 이동하고 강조 표시한다.
- Recovery Mode: 피해 발생 시 기존 Case의 맥락·근거·Timeline을 재사용해 지급정지·신고·피해구제·기기/계정보호 업무를 이어간다.

상세 요구사항과 비목표는 상위 PRD를 기준으로 한다.

## 2026-09-03 확정 범위

- 현재 MVP의 상담 수단은 텍스트 채팅과 구조화 카드다.
- 음성 통화 상담, 전화/WebRTC 연결, 녹음, 실시간 STT, 화자 분리, 음성 분석은 구현하지 않고 후속 확장으로 보류한다.
- 기존 voice 관련 소스는 참고용 휴면 코드이며 현재 고객·은행 라우트에 노출하지 않는다.
- 이미지·문서 첨부는 현재 범위다. 원본은 서버에, 메타데이터와 메시지 연결은 DB에 저장하며 공개 범위를 채널과 동일하게 적용한다.
- AI의 첨부 원문 분석/OCR/RAG 색인은 이번 Frontend 우선 단계가 아니라 AI·Backend 후속 연동 항목이다.

## 업무 실행 카드 원칙

- 은행 AI 개인 작업공간의 핵심 업무는 `미확인 정보, 고객 질문, 기관 검증, 보호조치, 고객 안내, Case 상태 변경` 카드로 제공한다.
- 고객 질문 답변은 AI/함수 처리 결과인 CaseFact 후보와 연결되고, 은행 AI 개인 작업공간에는 질문·답변을 함께 보여주는 얇은 접수 카드로 나타난다.
- 은행 화면의 `확인 및 확인중 정보` 패널은 직원이 요청한 모든 질문과 답변 대기/완료 상태를 일괄 조회한다.
- 피해구제 모드에서는 오른쪽에 진행 상황과 간단한 4단계 메뉴를 고정하고, 선택한 단계의 상세 절차·주의사항·공식 연락처·지원 요청은 채팅 안의 큰 카드로 표시한다.
- 고객도 상담 메시지를 Case별로 북마크하고 전용 목록에서 원문으로 이동할 수 있다.
- 고객이 `이미 사기 당했어요`를 선택한 사실은 일반 은행 협업 대화에 게시하지 않는다. `AI 개인 작업공간`에는 즉시 확인이 필요한 긴급 알림 카드로, `사건 진행 현황`에는 피해 발생 상태 변경 이벤트로 각각 표시한다.
- 피해 신고 알림과 후속 지원 요청은 구분한다. 피해 신고는 AI 개인 작업공간과 사건 진행 현황에만 노출하고, 고객이 특정 피해구제 단계에서 은행 담당자 지원을 요청한 경우에만 담당 업무 채널로 전달한다.
- 카드의 공통 생명주기는 `초안 → 검토 대기 → 처리 중 → 등록/전달 완료 또는 실패`다.
- AI와 Backend는 향후 `card_type + payload + stage`를 반환하고 Frontend 카드 레지스트리가 해당 컴포넌트를 호출한다.
- 실제 금융조치나 외부 기관 요청은 자동 실행하지 않으며, 해당 카드는 내부 업무/검증 Task 등록까지만 수행한다.
- 고객에게 전달되는 카드·메시지는 은행 내부 분석과 위험 점수를 포함하지 않는다.
