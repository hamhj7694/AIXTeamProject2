# 260903 Part 1 — Frontend-first 1차 목표

기준일은 2026-09-03이다. Backend·AI 담당자가 독립적으로 구현하는 동안 Frontend는 PRD의 Chat-first 작업 흐름을 먼저 완성하고, 실제 API를 교체 연결할 수 있는 타입·adapter 경계를 유지한다.

## 목표

1. 은행·고객·기관 검증 채널의 사용자별 말풍선·공개 범위를 명확히 구분한다.
2. 은행 담당자가 질문, 미확인 정보, 기관 검증, AI 응답 공유를 카드 단위로 처리하게 한다.
3. 사건 진행 현황, CaseFact, 검증 근거, 메모, 북마크를 Case 단위로 연결한다.
4. 고객 Bundle에는 은행 내부 정보와 통화 원문을 노출하지 않는다.
5. 기능별 Frontend 상태와 서버 저장 상태를 구분하여 문서화한다.

## 이번 작업 범위

- 메시지 작성자·역할·공개 범위 기반 말풍선 정렬
- 은행 내부/외부/AI 개인 채널 시각 구분
- 고객 질문 추천·직접 질문·선택지/직접 답변 카드
- 사건 진행 현황과 관련 메시지 이동
- 개인 메모 자동저장 UI
- 은행 메시지 개인 북마크와 원문 이동
- CaseFact 후보 검토·담당자 확정 UI
- 완료된 기관 검증 결과·확인자·RAG 출처·근거 표시

## 완료 기준

- `npm.cmd run build`가 성공한다.
- 공개 범위별 화면에서 허용된 메시지만 보인다.
- 버튼이 단순 안내문이 아니라 상태를 가진 카드 또는 명시된 후속 계약으로 연결된다.
- Frontend 임시 저장소는 adapter로 격리하고 서버 원본 전환 지점을 `05_DATA_SCHEMA_AND_FLOW.md`에 기록한다.
- 세부 상태는 `06_LIVE_DETAILED_IMPLEMENTATION_TODO.md`와 작업 로그에 즉시 반영한다.

## 현재 제약

- General API `http://127.0.0.1:8000`이 실행 중이어야 CaseFact·검증 결과의 실제 상호작용을 확인할 수 있다.
- 북마크는 현재 Frontend `localStorage` adapter이며 Backend Bookmark API/SQLite/권한 검증은 별도 담당 범위다.
- 보고서의 브라우저 저장소도 후속 서버 영속화 대상이다.
## 범위 결정 — 음성 통화 상담

2026-09-03 1차 목표에서는 음성 통화 상담을 구현하지 않는다. 전화/WebRTC, 녹음, 실시간 STT, 화자 분리, 음성 분석은 후속 확장이다. 현재 목표는 텍스트 Chat-first 고객 상담, 은행 협업, 기관 검증, 구조화 카드, 첨부파일, 보고서와 공유 Case 데이터의 완성이다.

기존 음성 관련 코드는 활성 라우트에 연결하지 않고 참고용으로 보존한다. 재개할 때 별도 PRD와 개인정보·녹음동의·보존·접근권한 정책을 먼저 작성한다.
