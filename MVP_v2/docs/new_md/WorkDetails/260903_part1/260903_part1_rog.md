# 260903 Part 1 작업 로그

## 1단계 — 메시지·권한 계약

1. 채팅 메시지에 작성자 ID·표시 이름·역할·공개 범위·메시지 유형을 추가했다.
2. 은행 화면에서는 현재 은행 직원 본인 메시지만 오른쪽에 표시한다.
3. 고객 화면에서는 현재 고객 본인 메시지만 오른쪽에 표시한다.
4. 다른 직원, AI, 검증 담당자의 메시지는 왼쪽에 표시한다.
5. 고객용 Case Bundle에서는 내부 메시지·검증 Task·은행 조치·Live Log·통화 원문을 제외했다.
6. 기존 저장 메시지도 기본 작성자 정보로 호환되도록 처리했다.
7. CORS에 Frontend 5175 포트를 추가했다.
8. Backend 계약 테스트와 Frontend 프로덕션 빌드를 통과했다.

### 1단계 점검 사항

- 현재 사용자 판정은 메시지 역할이 아니라 `actor_user_id === currentUserId`를 사용한다.
- 고객 공개 범위와 은행 내부/AI 개인 범위를 화면과 API에서 함께 확인해야 한다.
- 실제 인증 도입 시 Frontend가 보낸 actor 값을 신뢰하지 않고 서버 인증 주체로 덮어써야 한다.

## 1-2단계 — Chat-first 화면 세부 조정

1. 은행 협업·AI 개인 작업공간은 다크 모드, 고객 대화는 라이트 모드로 구분했다.
2. 빠른 AI 작업 버튼은 즉시 메시지를 발송하지 않고 기능 카드를 연다.
3. 질문 추천 카드에 AI 후보 선택, 직원 직접 질문 추가, 고객 질문 대기열 전달을 연결했다.
4. 고객 질문 카드에 선택지와 직접 입력 답변을 제공했다.
5. 사건 진행 현황은 업무 이벤트만 누적하고, 관련 메시지를 클릭하면 채널과 원문으로 이동한다.
6. 은행 정보 레일을 채팅 왼쪽에 배치하고 채팅 높이를 확장했다.
7. 개인 메모 위젯에 Case별 조회·생성·수정·삭제와 700ms 자동저장을 연결했다.

## 1-3단계 — 북마크·CaseFact·검증 결과

1. 은행 담당자 메시지에 개인 북마크 추가·해제 버튼을 추가했다.
2. Case·사용자별 북마크 목록과 채널명을 제공했다.
3. 북마크 클릭 시 원래 은행 협업/고객 대화/AI 개인 작업공간으로 전환하고 원문을 스크롤·강조한다.
4. 고객 화면에는 은행 담당자용 북마크 액션이 노출되지 않도록 제한했다.
5. `미확인 정보` 기능을 CaseFact 검토 카드로 교체했다.
6. CaseFact의 출처·신뢰도·후보/확정 상태를 표시하고 담당자 확정 API를 연결했다.
7. 후보/확정 CaseFact를 은행 정보 레일에서 상태별로 표시했다.
8. 완료/확인 불가 기관 검증 결과의 결과 요약·확인자·RAG 출처·근거 URL·고객 공개 가능 상태를 내부 카드로 표시했다.
9. 근거 URL은 HTTP/HTTPS 프로토콜만 열도록 제한했다.
10. `npm.cmd run build` 성공: TypeScript 및 Vite 프로덕션 빌드 통과.
11. 은행 화면 상단의 보고서 버튼을 현재 화면에 따라 `보고서 보기`와 `채팅 보기`로 전환되는 토글로 변경했다.
12. 은행 내부 채널 탭은 `은행 협업 → AI 개인 작업공간` 순서로 배치하고, 기본 진입 채널도 은행 협업으로 유지했다.
13. 보고서에서 채팅·로그 원문 나열을 제거하고 Case 기본 정보, 확정 Fact, 검증 결과, 미확인 사항, 권고 대응을 종합한 문서형 템플릿으로 변경했다.
14. 보고서 생성 시 은행 협업 채널에 한 줄 업무 알림을 남기도록 연결했다.
15. 직원 질문 카드 전달과 고객 질문 답변을 은행 협업 채널의 내부 업무 알림으로 동기화했다. 고객 피해 신고 알림은 후속 요구에 따라 AI 개인 작업공간과 사건 진행 현황으로 이동했다.
16. `SYSTEM_EVENT` 메시지를 일반 말풍선이 아닌 구분된 업무 알림 카드로 렌더링했다.
17. 은행 채팅 높이를 690px, 좌측 사건 진행/정보 레일을 734px로 줄여 한 화면에서 확인하기 쉽게 조정했다.
18. 좌측 레일에서 사건 진행 현황은 40%, 우선 조치 및 위험요소는 60% 높이를 사용하도록 비율을 조정했다.
19. 이미지·문서 첨부 계약, 서버 파일 저장, SQLite/MySQL 메타데이터, 메시지 연결, 은행·고객 채팅 UI를 구현했다.
20. 고객 공개가 아닌 첨부의 고객 조회를 차단하고 서버 내부 저장 경로가 Public 응답에 노출되지 않도록 했다.
21. AI가 후속 처리할 수 있도록 `ai_readable` 메타데이터와 내부 목록을 제공하되, OCR·문서 파싱·RAG 색인은 미구현 후속 항목으로 분리했다.
22. 현재 실제 라우트가 새 텍스트 Chat-first 은행·고객 화면을 사용하며 기존 음성 통화 UI는 연결되지 않음을 확인했다.
23. 음성 통화 상담, 녹음, 실시간 STT, 화자 분리, 음성 분석을 2026-09-03 MVP 범위에서 제외하고 후속 PRD 대상으로 기록했다.
24. 업무를 미확인 정보·고객 질문·기관 검증·보호조치·고객 안내·Case 상태 변경 6종 카드로 기획했다.
25. `WorkCardDescriptor`와 카드 카탈로그/레지스트리를 추가해 버튼 또는 향후 AI/API 응답이 타입별 카드 컴포넌트를 호출하도록 구성했다.
26. 보호조치 업무 등록, 고객 공개 안내, Case 상태 전환 카드를 구현했다.
27. Case 상태 카드는 Backend가 허용하는 다음 단계만 표시하고 담당자의 명시 확인 후 변경하도록 제한했다.
28. 카드의 원본 실행 성공 후 협업 알림이나 재조회만 실패한 경우 부분 성공 경고로 분리해 중복 실행을 방지했다.
29. 일반 통화·정상 금융 상담·보이스피싱 버튼에 각각 실제 5문장 샘플을 연결했다.
30. 고객 공개 카드용 `CustomerCardDescriptor`와 질문·답변 접수·검증 결과 렌더러를 추가했다.
31. 은행이 선택한 질문의 고객용 설명, AI 선택지, 답변 방식, 직접 입력 허용값이 질문 큐에서 보존되도록 계약을 확장했다.
32. 고객 질문 카드에서 내부 사유를 숨기고 맞춤 설명·선택지·직접 입력·답변 전송 UI를 구현했다.
33. 답변 완료 후 제출 내용을 확인하는 접수 카드를 표시하고 해당 답변이 CaseFact 후보임을 안내했다.
34. 완료·고객 공개 승인·결과 요약 조건을 만족한 기관 검증만 최소 필드로 고객 카드에 전달했다.
35. `이미 사기 당했어요` 버튼 클릭 시 채팅 내부가 아니라 오른쪽 `피해구제 안내` 칸이 4단계 상호작용 카드로 교체되도록 변경했다.
36. 피해구제 단계의 AI 조언/담당자 지원 요청을 고객 메시지와 은행 협업 알림에 함께 기록했다.
37. 고객 질문 projection을 명시적 허용 필드 변환으로 변경해 내부 사유 노출과 `extra=forbid` 런타임 오류를 방지했다.
38. 은행 직원이 고른 AI 추천 질문과 직접 입력 질문을 고객용 설명·선택지·직접 입력을 가진 구조화 질문 카드로 전달했다.
39. 고객 공개 카드 레지스트리에 질문, 답변 접수, 공개 검증 결과를 연결하고 피해구제 안내는 채팅 밖 오른쪽 안내 영역의 상호작용 카드로 분리했다.
40. Customer Agent의 질문 말풍선과 동일 질문 카드가 중복 표시되지 않도록 고객 메시지 렌더링을 정리했다.
41. 고객의 `answer_text/answered_at`을 Question 데이터에 영속화해 새로고침 후에도 실행 완료·답변 접수 카드가 복원되도록 했다.
42. 원본 업무 성공 뒤 협업 알림이나 화면 재조회만 실패한 경우 부분 성공 경고로 분리해 질문·피해구제 요청의 중복 실행을 막았다.
43. Frontend 프로덕션 빌드와 Backend 전체 계약·엔드포인트 테스트를 다시 실행했다.
44. 기능 카드를 채팅의 최신 위치로 옮기고 카드 실행 중 `아직 대화가 없습니다.` 안내가 함께 나타나지 않도록 공통 Chat Shell을 정리했다.
45. 고객 화면의 중복 `현재 확인 중` 카드와 정적 `피해구제 안내` 카드를 삭제했다.
46. `이미 사기 당했어요` 선택 전에는 안전 상담 안내를, 선택 후에는 같은 위치에 보이스피싱 피해 구제 안내 카드를 표시하도록 상태 전환을 정리했다.
47. 고객 질문 답변을 Question 원본 데이터에서 읽어 은행 AI 개인 작업공간에 질문·답변이 함께 담긴 얇은 접수 카드로 표시했다.
48. 북마크 옆에 `확인 및 확인중 정보` 버튼을 추가하고 전체 고객 질문·답변의 대기/완료 상태를 조회하는 패널을 구현했다.
49. Case별 피해구제 안내 활성 상태를 로컬 UI adapter에 저장해 다른 화면을 다녀온 뒤에도 동일한 안내 상태가 복원되도록 했다.
50. 오른쪽 피해구제 안내를 작은 4단계 선택 메뉴로 고정하고 메뉴 내부의 상세 펼침 UI를 제거했다.
51. 즉시 연락·증빙 확보·신고 접수·구제 신청을 선택하면 채팅 최신 위치에 순서·주의사항·공식 연락처가 담긴 큰 절차 카드가 생성되도록 했다.
52. 상세 피해구제 카드에서 AI 맞춤 조언과 은행 담당자 지원을 요청하고 양쪽 채널에 기록하는 기존 흐름을 연결했다.
53. 피해구제 모드의 닫기 동작을 제거하고 Case별 활성 모드와 마지막 선택 단계를 로컬 UI adapter에 보존했다.
54. 고객 채팅 메시지에도 북마크 버튼을 활성화하고 고객 전용 북마크 목록과 원문 스크롤 이동을 추가했다.
55. Frontend 프로덕션 빌드를 다시 실행해 TypeScript와 Vite 빌드가 통과했다.
56. 고객이 `이미 사기 당했어요`를 선택하면 일반 은행 협업 채널에는 알림을 만들지 않고 `AI_INTERNAL/AI_PRIVATE` 긴급 알림을 생성하도록 변경했다.
57. 같은 동작에서 Case 피해 여부를 `YES`로 갱신하고, 생성된 `CASE_FIELD_UPDATED` 이벤트를 사건 진행 현황의 `고객 피해 발생 신고` 경고 항목으로 표시했다.
58. 피해 신고 자체와 이후 상세 피해구제 카드의 AI 조언·은행 담당자 지원 요청을 서로 다른 업무 이벤트로 구분했다.
59. 고객 피해구제 안내는 오른쪽의 단계 선택 메뉴, 상세 절차는 채팅 안 대형 카드라는 역할 분리를 유지하고 고객 메시지 북마크·전용 목록·원문 이동 상태를 문서 계약에 반영했다.
60. 고객 피해 신고를 전용 `customer-emergency` 서버 명령 하나로 통합해 고객 확인 메시지, Case `RECOVERY` 전환, 피해 상태 `YES`, AI 개인 긴급 알림을 함께 생성하도록 변경했다.
61. 반복 클릭·재요청 시 기존 고객 확인 메시지와 AI 긴급 알림을 재사용해 중복 생성을 막도록 보완했다.
62. Case 공용 AI 긴급 알림으로 저장해 특정 은행 직원 ID에 종속되지 않고 AI 개인 작업공간에서 담당자가 확인할 수 있게 했다.
63. 고객 화면의 피해구제 모드는 서버 `mode=RECOVERY` 또는 피해 상태 `YES`에서 복원하고 브라우저 저장값은 보조 상태로 낮췄다.
64. 고객 질문 답변 후 별도의 은행 `TEAM` 알림을 만들던 중복 경로를 제거하고 Question Queue 기반 질문·답변 접수 카드만 사용하도록 통일했다.
65. 사건 진행 현황의 `고객 피해 발생 신고`를 클릭하면 AI 개인 작업공간으로 전환해 해당 긴급 알림 메시지로 스크롤·강조하도록 연결했다.
66. MySQL에 없는 임시 Case 컬럼을 저장하지 않도록 정식 Case 필드만 갱신하고, 연결 메시지는 Bank Bundle의 저장 메시지에서 찾도록 DB 호환성을 보완했다.
67. Backend 계약 테스트 27건과 Frontend TypeScript/Vite 프로덕션 빌드를 통과했다.
68. 고객 URL은 하나였지만 구형 고객 화면 구현 세 벌과 중복 개발 서버가 혼동을 만들고 있음을 Frontend·UX·디버깅 에이전트가 함께 확인했다.
