## 미래 완성 로드맵

이 로드맵은 위 세부 TODO가 모두 완료된 뒤 끝나는 계획이 아니라, 서비스가 실제 운영 가능한 Context-First Case 플랫폼으로 발전하기 위한 다음 단계다. 우선순위가 바뀌면 이 표를 먼저 수정하고, 영향을 받는 세부 항목을 다시 연결한다.

### Phase 1 — MVP 핵심 흐름 완성

목표: 하나의 의심 통화가 Case가 된 뒤 고객 상담·은행 협업·기관 검증·보호조치·종료 또는 Recovery까지 같은 데이터로 재현된다.

- 검증 결과/근거/RAG 출처/고객 공개 승인 UI 완성
- CaseFact·Verification·BankAction·Event의 화면 간 동기화
- 개인 메모와 북마크로 담당자의 사건 파악·인수인계 지원
- 서버 기반 보고서 버전·휴지통·최종 보고서 스냅샷
- Recovery Mode 및 피해구제 Action 카드
- 핵심 E2E 시연 시나리오와 고객 내부정보 누출 회귀 테스트

완료 판단: PRD의 Acceptance Criteria 전체와 `J-09` 시나리오가 로컬 SQLite 환경에서 재현된다.

### Phase 2 — 팀 협업·실시간 운영 전환

목표: 여러 담당자가 같은 Case를 동시에 보고 작업해도 정보 누락·중복·충돌이 관리된다.

- 실제 인증/RBAC와 서버 기준 역할 판정
- SSE/WebSocket 기반 Case Event 실시간 동기화
- 동시 편집 version conflict, 읽음/presence, 담당자 인수인계 기록
- 팀 공유 북마크·공유 메모 권한 정책
- 서버 측 검색·필터·페이지네이션·감사 로그
- 운영 모니터링, 오류 알림, 데이터 백업/복구 정책

완료 판단: 서로 다른 역할의 두 사용자 세션에서 고객 공개 경계와 실시간 Timeline 갱신이 검증된다.

### Phase 3 — AI/RAG 업무 품질 고도화

목표: AI가 단순 답변 생성이 아니라 근거 있는 질문·검증·설득·피해구제 업무를 안정적으로 보조한다.

- PREVENT 6모듈·RECOVERY 6모듈 지식베이스 구축
- RAG 문서 메타데이터(출처·최신성·적용 범위·승인 상태) 관리
- Customer/Bank/Verification Agent별 프롬프트·입출력 계약·평가셋
- AI 제안 승인/수정/거절 데이터 기반 품질 측정
- 위험한 조언·근거 없는 기관 정보·고객 공개 위반에 대한 안전성 평가
- Case Orchestrator의 Event 기반 작업 분배와 병렬 Agent 호출 정책

완료 판단: 대표 사기 유형별 평가셋에서 출처 포함 답변, 승인 흐름, 공개 범위가 기준치를 충족한다.

### Phase 4 — 실제 외부 데이터 연계 준비

목표: 통신·금융·기관 데이터를 직접 연동하기 전에 최소 정보·감사·권한 원칙을 갖춘 연계 계약을 확정한다.

- 통신 AI Context Feature Schema(사칭주체·주장·요구·긴급성·금액·계좌·위험발화·순서) 정의
- FDS/ASAP 위험 신호와 Case ID 연계 키·이벤트 API 정의
- 데이터 최소화·보존기간·마스킹·감사 로그·동의 정책 검토
- 기관 공식 절차/연락처/RAG 근거의 갱신 책임과 검증 절차 정의
- 외부 연계 실패·지연·중복 Event의 보상 처리 설계

완료 판단: 실제 운영망에 접속하지 않은 상태에서 계약 모의 테스트와 보안 검토를 통과한다.

### Phase 5 — 운영 확장·성과 측정

목표: 서비스가 피해 예방과 복구 업무의 품질·속도·누락률을 측정하며 지속적으로 개선된다.

- 담당자 최초 사건 이해 시간, 필수 질문/검증 누락률, AI 승인률 측정
- 고객 질문 응답 완료율·안전행동 안내 확인율·Recovery 준비 시간 측정
- 담당자 변경 후 파악 시간, 재설명 횟수, Timeline/북마크 활용도 측정
- KPI 대시보드와 개인정보를 포함하지 않는 운영 분석 데이터셋
- 정기 UX 검토·접근성 검토·RAG 문서 갱신·모델 평가 프로세스

완료 판단: KPI 변화와 사용자 피드백을 다음 분기의 PRD·세부 TODO에 반영하는 운영 루프가 실행된다.
