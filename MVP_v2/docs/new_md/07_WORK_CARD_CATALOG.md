# Chat-first 업무 실행 카드 카탈로그

기준일: 2026-09-03

## 목적

은행 직원과 AI가 채팅 안에서 수행하는 업무를 단순 문자열이 아니라 구조화 카드로 호출한다. Frontend는 `card_type + payload + stage`를 받아 카드 레지스트리에서 렌더링하고, Backend/AI는 동일한 `WorkCardDescriptor` 형태로 카드 초안이나 기존 카드 상태를 전달할 수 있어야 한다.

음성 통화·녹음·STT 카드는 현재 범위에 포함하지 않는다.

## 공통 상태

| 상태 | 의미 | 허용 행동 |
|---|---|---|
| `DRAFT` | 입력 전 또는 AI 초안 | 값 입력·수정·닫기 |
| `READY` | 필수값 충족, 사람 검토 대기 | 수정·승인/실행 |
| `SUBMITTING` | 서버 요청 처리 중 | 중복 실행 차단 |
| `REGISTERED` | Case 내부 업무 등록 성공 | 결과 확인·원문 이동 |
| `DELIVERED` | 고객 등 대상 채널 전달 성공 | 전달 결과 확인 |
| `FAILED` | 핵심 실행 실패 | 오류 확인·안전한 재시도 |

핵심 실행 성공 후 협업 알림만 실패한 경우 전체 실패로 되돌리지 않는다. “실행 성공·알림 동기화 실패” 경고를 표시해 중복 실행을 막는다.

## 현재 우선 카드

| `card_type` | 카드 | 사용하는 사람/채널 | 입력 | 실행 결과 | 고객 영향 |
|---|---|---|---|---|---|
| `FACT_REVIEW` | 미확인 정보 검토 | 은행 / AI 개인 작업 | CaseFact 후보, 근거, 신뢰도 | 담당자 확정 Fact 또는 후속 질문 | 직접 노출 없음 |
| `QUESTION_PLAN` | 고객 질문 구성 | 은행 / AI 개인 작업 | AI 후보, 직원 직접 질문, 선택 목록 | 고객 질문 대기열 | 질문 카드 순차 노출 |
| `VERIFICATION_REQUEST` | 기관 검증 요청 | 은행 / AI 개인 작업 | 사칭 주장, 확인 대상 | Verification Task | 승인된 결과만 추후 노출 |
| `BANK_ACTION` | 보호조치 업무 등록 | 은행 / AI 개인 작업 | 업무 유형, 업무 내용 | `REQUESTED` BankAction | 실제 금융조치 자동 실행 없음 |
| `CUSTOMER_NOTICE` | 고객 안내 작성 | 은행 / AI 개인 작업 | 공개 가능한 안내문 | 고객 채널 메시지 | 즉시 고객에게 전달 |
| `CASE_TRANSITION` | Case 상태 변경 | 은행 / AI 개인 작업 | 허용 다음 단계, 확인 체크 | Case 상태·모드 변경 | 공통 진행 상태에 반영 |

## 관리 UI로 유지하는 기능

- 담당자 배정과 참여자/presence 관리는 화면 상단 관리 UI로 유지한다.
- 보고서 목록·생성·버전·휴지통은 보고서 화면에서 관리한다.
- 사건 종료는 최종 보고서 생성이 결합된 별도 확인 모달을 사용한다.
- 파일 첨부는 메시지 작성기의 공통 기능이며 별도 업무 카드가 아니다.

## 고객 공개 카드

| 카드 | 입력 원본 | 고객에게 표시 | 고객 행동 | 내부 연동 |
|---|---|---|---|---|
| 맞춤 질문 | 은행 선택/AI 생성 `Question` | 질문, 고객용 한 줄 설명, 선택지 | 단일 선택 또는 직접 입력 후 답변 | 답변 Message + CaseFact 후보 + 다음 질문 |
| 답변 접수 | 방금 완료한 Question/Answer | 질문과 제출 답변, 후보 상태 안내 | 닫기 | AI 개인 작업공간의 질문·답변 접수 카드, 담당자 Fact 검토 |
| 공식 확인 결과 | 고객 공개 승인된 완료 Verification | 대상, 결과 요약만 표시 | 상담에서 추가 질문 | 내부 근거·RAG·확인자 미노출 |
| 현재 진행 상황 | Case status/mode, 질문 상태, 공개 검증 수 | 5단계 진행과 건수 | 읽기 | 같은 Case 상태 사용 |
| 피해구제 안내 | 고객의 `이미 사기 당했어요` 요청 | 즉시 연락·증빙·신고·구제 절차 | 단계 선택, AI 조언/담당자 지원 요청 | 고객 Message + Case 상태 Event + AI_PRIVATE 긴급 알림 |

질문 payload는 `question_text, customer_explanation, options, answer_mode, allow_free_text, sequence`를 고객에게 제공한다. `reason, requested_by, 내부 우선순위 판단 근거`는 고객 projection에서 제거한다. 답변 후에는 `answer_text/answered_at`만 같은 고객에게 반환해 접수 카드를 복원한다. 고객 카드 렌더러는 discriminated `card_type`에 따라 질문·답변 접수·검증 결과 컴포넌트를 호출하며, 같은 질문의 일반 말풍선은 중복 표시하지 않는다.

피해구제 안내는 채팅 스트림 안이 아니라 고객 화면 오른쪽의 `안전 상담 안내`를 교체하는 상태형 카드다. 고객이 `이미 사기 당했어요`를 누르기 전에는 안전 상담 안내를, 누른 뒤에는 보이스피싱 피해 구제 안내만 표시해 페이지 구조와 채팅 폭을 유지한다.

오른쪽 피해구제 안내 자체는 `즉시 연락/증빙 확보/신고 접수/구제 신청` 메뉴만 가진다. 버튼을 누르면 `RECOVERY_STEP` 고객 카드가 채팅 최신 위치에 크게 생성되며, 카드 안에서 순서별 절차를 읽고 AI 조언 또는 은행 담당자 지원을 요청한다. 단계 선택은 외부 업무 실행이 아니며, 지원 요청 시에만 Case 메시지와 은행 협업 알림을 생성한다.

`이미 사기 당했어요`를 누른 최초 피해 신고는 은행 협업 채널 알림과 구분한다. 신고 사실은 `AI 개인 작업공간`의 긴급 알림 카드와 `사건 진행 현황`의 피해 발생 상태 이벤트에만 나타난다. 사용자가 이후 상세 카드에서 은행 담당자 지원을 명시적으로 요청한 경우에만 협업 업무 알림 또는 BankAction을 생성한다.

은행 AI 개인 작업공간에는 답변이 완료된 Question을 `질문 + 고객 답변 + CaseFact 후보 상태`로 축약한 얇은 접수 카드를 표시한다. 전체 이력은 북마크 옆 `확인 및 확인중 정보` 패널에서 질문 대기·답변 대기·답변 완료 상태별로 조회한다.

## Frontend 호출 구조

1. `catalog.ts`가 은행에서 사용 가능한 카드와 빠른 작업 버튼을 제공한다.
2. 버튼 클릭 또는 향후 AI/API 응답이 `WorkCardDescriptor`를 생성/수신한다.
3. `WorkCardRenderer.tsx`가 `card_type`에 맞는 독립 카드 컴포넌트를 호출한다.
4. 활성 기능 카드는 채팅 내역의 아래, 입력창과 가까운 최신 위치에 표시하며 빈 대화 안내와 동시에 노출하지 않는다.
5. 카드가 원본 API를 먼저 실행한다.
6. 성공 결과는 카드의 완료 상태와 대상에 맞는 업무 Event 또는 채널 알림에 반영한다.
7. 고객 공개 동작은 명시적 전송 버튼을 누른 카드만 수행한다.
8. 고객 화면은 `CustomerCardRenderer`가 공개용 descriptor만 받아 내부 카드와 다른 컴포넌트로 변환한다.

현재 빠른 작업 버튼은 Frontend가 `source=USER_ACTION`인 초안 descriptor를 만든다. AI/Backend 연동 후에는 서버가 `card_id`, `card_type`, `stage`, `payload`, `source`, `created_at`을 반환하고 Frontend는 같은 레지스트리로 렌더링한다.

## 후속 카드

- 검증 결과 고객 공개 승인 카드
- BankAction 진행/완료/실패 갱신 카드
- 피해구제 단계별 Action 카드
- 개인 메모의 내부 공유/Fact 후보 전환 카드
- AI 제안 공유·수정·거절 카드
- 첨부파일 AI 분석 요청/결과 카드

## 완료 기준

- 실행 전 필수값과 공개 범위를 확인할 수 있다.
- 처리 중 중복 클릭이 차단된다.
- 핵심 실행 성공/실패와 부가 알림 실패가 구분된다.
- 고객 전달 카드는 내부 정보가 없는 payload만 사용한다.
- 실행 결과가 새로고침 후에도 서버 Case 데이터·메시지·Event에서 확인된다.
- Backend 계약이 없는 기능은 실제 실행처럼 표시하지 않는다.
