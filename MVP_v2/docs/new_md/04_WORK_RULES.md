# MVP_v2 작업 규칙

- Codex는 단순 파일 작성자가 아니라 Lead Engineer·Product Engineer·QA·UX·Architecture Reviewer로서 실제 사용자 E2E 완료를 기준으로 작업한다.
- 새 요청을 받을 때 관련 파일 하나만 보지 않고 저장소 구조, Git diff, PRD, 데이터 계약, migration, API, Frontend, AI/ML, 테스트, TODO/FIXME와 중복 정본을 함께 확인한다.
- 작업 루프는 `분석 → 계획 → 구현 → 실행 → 테스트 → 결과 점검 → UX 점검 → 연관 문제 수정 → 재검증 → 다음 P0` 순서로 이어간다.
- 안전하고 가역적인 명백한 버그 수정·타입 정리·테스트·문서 갱신은 스스로 진행한다. 핵심 정책·권한·대량 데이터 삭제·운영 배포·유료 API 대량 호출은 사용자 확인 없이 실행하지 않는다.
- 완료는 코드 존재가 아니라 Frontend↔General API↔DB↔AI API 데이터가 실제 사용자 시나리오에서 연결되고 Loading·Empty·Error·중복 요청·새로고침까지 검증된 상태를 의미한다.
- 문서와 코드가 충돌하면 최근 코드·migration·OpenAPI·테스트·실행 화면을 종합해 정본을 판별하고, 최종적으로 문서와 구현을 일치시킨다.
- 임시 Mock·placeholder·hardcoded 사용자·localStorage 업무 원본을 최종 구현으로 보고하지 않는다. 필요한 임시 요소에는 교체 조건과 실제 연동 TODO를 남긴다.
- 화면 문구와 정보 위계는 개발자 필드명이 아니라 실제 은행 직원과 고객이 처음 읽어도 `무엇을 확인했고 무엇을 해야 하는지` 알 수 있는 표현을 사용한다.
- Git 충돌 표식, 중복 구현, 오래된 화면, 사용되지 않는 API/컴포넌트를 주기적으로 검사하되 사용자 데이터를 추정하여 삭제하지 않는다.
- 상위 PRD와 `05_DATA_SCHEMA_AND_FLOW.md`를 먼저 읽는다.
- 데이터 필드 변경은 계약 → 저장소 → API → Frontend → 테스트 → 문서 순으로 반영한다.
- 고객에게 BANK_INTERNAL·AI_INTERNAL·내부 검증 근거·위험 점수를 노출하지 않는다.
- AI는 DB 직접 수정·승인 없는 고객 발송·외부 기관 자동 요청을 하지 않는다.
- 확인되지 않은 값은 `확인안됨`으로 표시하고 추정하지 않는다.
- 기능 카드는 초안 → 실행 완료 → 대상 채널 전달 상태를 채팅에 남긴다.
- 개인 메모는 `private-to-author`가 기본이며 명시적 전환 전에는 다른 사용자·AI·고객에게 노출하지 않는다.
- 북마크는 원본 Message/Card를 수정하지 않는 개인 바로가기이며, 원본 삭제·권한 변경 시 접근권한을 다시 확인한다.
- 고객 발송, Fact 확정, BankAction, 상태 변경은 사람의 명시적 승인/확정 액션 없이는 실행하지 않는다.
- 모든 완료 작업은 빌드/테스트/수동 경로를 기록한다.
- 로컬 Frontend는 `dist` 없이 Vite 개발 서버로 실행하고 `/api/*`를 General API로 프록시한다. Frontend가 AI API를 직접 호출하지 않는다.
- `dist`, `.vite`, 실행 로그는 생성 산출물이며 Git에 포함하지 않는다.
- 현재 MVP에서 음성 통화·녹음·실시간 STT 기능을 새로 연결하거나 활성 화면에 노출하지 않는다. 별도 후속 PRD 승인 전까지 구형 voice 구현은 정리 대상이며 재도입하지 않는다.
- 첨부 원본 경로는 서버 내부 값이며 API/Frontend에 노출하지 않는다. 첨부의 공개 범위는 연결 메시지의 공개 범위와 일치해야 한다.
- AI는 권한이 허용된 첨부만 읽고, 파싱되지 않은 파일 내용을 추정하지 않는다.
- 유료 AI 경로에는 호출 수·입출력 토큰·재시도·동시성·예상 비용의 Hard Limit을 적용하고, 테스트에서는 Mock/fixture를 우선한다.
