## 1단계 — 공통 메시지 계약·고객 화면 경계

### 완료 순서

1. 채팅 메시지 공개 계약에 아래 필드를 추가했다.
   - `actor_user_id`: 작성자 식별자
   - `actor_display_name`: 화면 표시 이름
   - `actor_role`: 업무 역할
   - `visibility`: `BANK_INTERNAL` / `CUSTOMER` / `AI_PRIVATE`
   - `message_kind`: `CHAT` / `AI_REQUEST` / `AI_RESPONSE` / `SYSTEM_EVENT`
   - `reply_to_message_id`: 답글·원문 연결용 식별자
2. 은행 화면에서 현재 은행 직원 본인(`currentUserId`)이 작성한 메시지만 오른쪽 말풍선으로 표시하도록 변경했다.
3. 고객 화면에서 현재 고객 본인이 작성한 메시지만 오른쪽 말풍선으로 표시하도록 변경했다.
4. 다른 은행 직원, Customer Agent, Bank Agent, 기관 검증 담당자 메시지는 왼쪽 말풍선으로 표시하도록 변경했다.
5. 고객용 Case Bundle에서 내부 메시지, 검증 Task, 은행 조치, Live Log 이벤트, 음성 세션, 초기 보고서를 제외했다.
6. 채팅 Bundle의 Case 정보는 통화 원문·내부 진단 원문을 포함하지 않는 화면용 `CaseSummary`로 제한했다.
7. 기존 SQLite에 저장된 이전 메시지는 작성자 ID·이름·공개 범위·유형의 기본값을 적용해 기존 데이터도 읽을 수 있도록 호환 처리했다.
8. 프론트 개발 서버 포트 `5175`에서 General API를 호출할 수 있도록 CORS 허용 목록에 `localhost/127.0.0.1:5175`을 추가했다.

| 프론트 프로덕션 빌드 | 통과 | `npm.cmd run build` 성공 |

### 확인이 필요한 사항

1. 은행 화면에서 현재 은행 직원 메시지만 오른쪽에 표시되는지 확인한다.
2. 고객 화면에서 고객 메시지만 오른쪽에 표시되는지 확인한다.
3. 고객 화면에서 내부 검증·조치·Live Log가 보이지 않는지 확인한다.
4. 현재 경계는 MVP 데모의 API Projection이다. 실제 인증/RBAC가 아직 없으므로, 다음 보안 단계에서 서버가 인증된 사용자 기준으로 역할과 접근 범위를 판정해야 한다.
5. 고객 상세 화면의 별도 `GET /api/cases/{id}` 호출은 아직 완전한 고객 전용 Read Contract로 교체되지 않았다. 고객 Bundle은 제한됐지만, 이 상세 조회 계약은 후속 정리 대상이다.

## 1단계 보완 — Case 허브의 중복 업무 안내 통합

### 완료 순서

1. 각 Case 허브에 있던 `지금 해야 할 일` 독립 카드를 제거했다.
2. 은행 대응 화면 좌측의 위험요소 영역을 `우선 조치 및 위험요소` 패널로 변경했다.
3. 해당 패널에서 다음 우선 업무를 기존 위험요소와 함께 표시하도록 통합했다.
   - 메인 담당자 미배정
   - 고객 피해 여부 및 실제 피해액 미확인
   - 미종결 Case인데 등록된 검증 요청이 없는 경우
4. Case 허브는 Case 상태, AI 초기 판단, 은행/고객/기관 검증 화면 진입점에 집중하도록 단순화했다.

### 점검·검증

| 항목 | 결과 | 내용 |
|---|---|---|
| 프론트 프로덕션 빌드 | 통과 | `npm.cmd run build` 성공 |
| 개발 서버 반영 | 정상 | Vite 개발 서버가 변경 사항을 자동 반영 |

### 2단계 전 점검 항목

1. `우선 조치 및 위험요소`의 높이와 스크롤이 Live Log와 함께 사용하기에 적절한지 확인한다.
2. 우선 업무를 단순 문구가 아닌 담당자·기한·상태를 가진 Action/Task로 저장할 데이터 계약을 2단계에서 설계한다.
3. 팀 대화, 고객 대화, AI 개인 작업공간을 UI에서는 연결해 보이되 DB 채널·공개 범위는 분리하는 방향을 구현한다.
4. 팀에 공유한 AI 답변과 개인 AI 초안을 구분하고, 공유 이벤트만 Live Log·보고서 근거로 남기도록 구현한다.

## 2단계 — 은행 협업 통합 타임라인·AI 개인 작업공간

### 완료 순서

1. 은행 화면의 채널 구성을 `은행 협업`, `고객 대화`, `AI 개인 작업공간`으로 변경했다.
2. 기본 `은행 협업` 화면은 TEAM 채널 메시지와 팀에 공유된 AI 답변만 함께 보여주는 통합 타임라인으로 구성했다.
3. `AI 개인 작업공간`은 현재 사용자에게 귀속된 AI 요청·답변만 표시하도록 필터링했다.
4. AI 개인 작업공간에서 은행 직원의 질문을 `AI_REQUEST` 메시지로 저장한 뒤, CaseCopilot 답변을 `AI_RESPONSE`로 저장하도록 변경했다.
5. 개인 AI 답변에는 `팀에 공유` 버튼을 표시하고, 클릭하면 같은 답변을 TEAM 채널의 은행 내부 공유 메시지로 복제하도록 API를 추가했다.
6. 공유된 AI 답변은 `BANK_INTERNAL` 공개 범위, `TEAM` 채널, 원본 AI 답변의 `reply_to_message_id`를 가지며 Live Log 이벤트로도 기록된다.
7. 은행 협업 대화에서 `@CaseCopilot`을 명시하면 팀 채널에 CaseCopilot 답변이 즉시 추가되도록 연결했다. 일반 팀 대화에는 AI가 자동 응답하지 않는다.
8. AI 응답 계약에 요청자 정보와 응답 채널을 추가해 개인 분석 답변과 팀 공개 답변을 구분했다.

### 점검·검증

| 항목 | 결과 | 내용 |
|---|---|---|
| 백엔드 계약 테스트 | 통과 | collaboration·public case read 테스트 총 4개 통과 |
| 프론트 프로덕션 빌드 | 통과 | `npm.cmd run build` 성공 |
| General API 재시작 | 정상 | `http://127.0.0.1:8100/health` → `status: ok` |
| AI 공유 API | 정상 | OpenAPI에서 `/api/cases/{case_id}/ai/messages/{message_id}/share` 확인 |
| Frontend | 정상 | `http://127.0.0.1:5175/cases` HTTP 200 확인 |

### 사용자 확인 항목

1. `은행 협업`에서 일반 팀 메시지는 AI가 자동으로 답하지 않는지 확인한다.
2. 팀 채팅에 `@CaseCopilot`을 포함하면 CaseCopilot 답변이 같은 협업 타임라인에 나타나는지 확인한다.
3. `AI 개인 작업공간`에서 AI 요청·답변이 나타나는지 확인한다.
4. 개인 AI 답변의 `팀에 공유`를 누르면 `은행 협업`에서 해당 답변이 보이는지 확인한다.
5. `고객 대화`에서는 고객 공개 메시지만 보이고, 개인 AI 답변은 보이지 않는지 확인한다.

### 남은 제약

- 현재 사용자 구분은 MVP 데모용 고정 사용자 값이다. 실제 로그인/RBAC 도입 전에는 다른 사용자가 API를 직접 호출해 개인 AI 답변을 조회하지 못하도록 완전히 차단할 수 없다.
- AI 공유는 원본을 수정하지 않고 팀 공유용 메시지를 별도 생성한다. 이후에는 공유자·공유 시각·공유 취소를 명시적으로 표시하는 모델을 추가한다.
- Live Log에 현재 AI 개인 분석 생성도 기록된다. 후속 이벤트 가시성 정책에서 개인 AI 이벤트는 팀 Live Log에서 제외하거나 개인 로그로 분리할지 결정한다.

### 2단계 보완 — 은행 채널 우선순위·통화 기능 보류

1. 은행 직원의 기본 업무 흐름을 내부 판단 → 고객 안내로 정리해, 탭 순서를 `은행 협업 → AI 개인 작업공간 → 고객 대화`로 고정했다.
2. 내부 채널(은행 협업·AI 개인 작업공간)은 검은색 그룹으로 묶고, 외부 채널(고객 대화)은 흰색 그룹으로 분리해 공개 범위를 시각적으로 구분했다.
3. AI 개인 작업공간 입력창 바로 위에 `Case 요약`, `우선 조치 정리`, `고객 확인 질문`, `검증 요청 초안` 빠른 요청 버튼을 추가했다.
4. 현재 고객 상담 화면의 `은행 담당자 연결` 통화 버튼을 제거했다.
5. 음성 통화 기능이 포함된 기존 `bank-v1` 라우트를 제거해 현재 MVP 경로에서 접근되지 않게 했다.
6. 프론트 프로덕션 빌드가 통과했고, 현재 MVP 라우트·화면에서 음성 통화 버튼 참조가 남지 않은 것을 확인했다.
