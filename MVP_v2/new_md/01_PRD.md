# Shared Case 보이스피싱 대응 플랫폼 PRD

## 제품 목적

의심 통화 텍스트를 문장 단위 ML로 분석한다. 최고 위험 점수가 임계값을 넘으면 하나의 Case를 생성하고, 고객·은행·검증 담당자·AI가 동일 Case의 근거와 업무 상태를 공유해 예방 또는 피해 복구를 지원한다.

핵심 원칙은 통화 맥락을 하나의 Case로 연결하고, 대화·근거·조치·보고서를 시간순으로 누적하는 것이다.

## 사용자와 화면

| 사용자 | 화면 | 목적 |
|---|---|---|
| 운영자/은행 직원 | /cases | Case 검색, 필터, 정렬, 휴지통 관리 |
| 은행 협업자 | /cases/:caseId/bank | 참여자 협업, AI 호출, Live Log, 보고서 |
| 고객 | /cases/:caseId/customer | 고객 상황 파악 및 안전 안내 |
| 검증 담당자 | /cases/:caseId/verify | 기관 사칭과 주장 진위 확인 |

## 핵심 흐름

1. 통화 텍스트 입력
2. 문장별 독립 ML과 전체 맥락 분석
3. 임계값 이상이면 순번 ID의 Case 생성
4. SQLite 로컬 DB에 Case 저장
5. 은행·고객·검증 화면이 같은 Case API를 통해 상호작용
6. 은행 담당자가 사건 종료 승인 시 최종 보고서 확정

## 핵심 데이터 원칙

| 항목 | 원칙 |
|---|---|
| ID | 사람 친화적 순번, 목록에서는 ID로 표시 |
| 피해 여부 | 확인안됨, 피해 발생, 피해 없음의 세 값 |
| 실제 피해 금액 | 실제 이체·손실액만 표시 |
| 요구 금액 | 사기범 요청 금액이며 피해 금액과 분리 |
| 업무 진행 상태 | 내부 코드를 한글 업무 상태로 변환 |
| 최근 업데이트 | 채팅, 담당자, 검증, 조치, 종료 등 의미 있는 업무 이벤트 기준 |

## MVP 기능 범위

- 실제 API 기반 통화 분석과 Case 생성
- Case 목록의 최신순 정렬, 필터, 검색, 휴지통
- 고객/은행/검증의 공통 Case 연동
- 은행 Chat-first 협업, 참여자, 담당자, AI 명시 호출
- Live Log와 위험요소 확인
- 보고서 생성, Word/PDF 내보내기

## 현재 제약과 다음 목표

- 보고서 목록과 휴지통은 현재 브라우저 저장소 기반이다. 팀 공유를 위해 DB API로 옮긴다.
- SQLite가 로컬 MVP 기본 저장소다. MySQL 휴지통 계약을 동일하게 구현해야 한다.
- 현재 15초 polling은 이후 SSE/WebSocket으로 교체한다.
