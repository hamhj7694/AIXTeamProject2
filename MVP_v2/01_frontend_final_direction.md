# 고객·은행 Frontend 최종 방향

## 1. 공통 UX 원칙

- 중앙 작업 공간은 채팅이다.
- 메시지 입력창은 채팅 영역 내부 하단에 `sticky` 또는 고정 형태로 배치한다.
- 입력창 위로 메시지·질문·검증·조치·결과 카드가 시간순으로 쌓인다.
- 화면 밖에는 현재 상태 판단에 꼭 필요한 정보만 둔다.
- 상세 근거와 과거 이력은 Drawer 또는 채팅 카드 펼치기로 확인한다.
- 고객과 은행은 동일한 `case_id`를 사용하지만, 메시지 Audience와 실행 권한을 분리한다.
- 화면을 갱신할 때 전체 페이지를 다시 그리지 않고 변경된 Entity만 Upsert 또는 Append한다.

## 2. 고객 화면

### 2.1 화면의 역할

고객 화면은 사건 조사용 Dashboard가 아니다. 다음 세 가지에 집중한다.

1. 고객이 위험 행동을 즉시 중단하게 한다.
2. Customer Agent가 필요한 사실을 질문하고 답변을 Case에 전달한다.
3. 은행·기관 확인이 어디까지 진행됐는지 고객이 이해할 수 있게 보여준다.

### 2.2 최종 Layout

```text
┌───────────────────────────────────────────────────────┐
│ Safety Bar: 지금 해야 할 행동 · 담당자 연결 상태       │
├───────────────────────────────────┬───────────────────┤
│                                   │ 현재 진행          │
│ Customer Agent Chat               │                   │
│                                   │ · 현재 단계        │
│ · 안내 메시지                      │ · 확인 중인 항목    │
│ · 상황 확인 질문                   │ · 다음 행동        │
│ · 고객 응답                        │                   │
│ · 기관 확인 상태                   │                   │
│ · 은행 담당자 메시지               │                   │
│                                   │                   │
│ ┌───────────────────────────────┐ │                   │
│ │ 첨부 · 메시지 입력 · 전송     │ │                   │
│ └───────────────────────────────┘ │                   │
└───────────────────────────────────┴───────────────────┘
```

모바일에서는 우측 `현재 진행` 영역을 상단의 접을 수 있는 Summary Card로 이동하고 채팅을 전체 폭으로 사용한다.

### 2.3 채팅 밖 필수 구성요소

| 구성요소 | 역할 | 표시 범위 |
|---|---|---|
| `SafetyActionBar` | 송금 중단·인증정보 미제공 등 가장 긴급한 행동 | 한 번에 1~2개 |
| `HumanConnectionBadge` | AI 상담·은행 확인·담당자 직접 참여 상태 구분 | 항상 표시 |
| `CustomerProgressMini` | 현재 단계와 다음 단계 안내 | 최대 3단계 |
| `NextActionMini` | 고객이 지금 수행할 한 가지 행동 | 1개 |
| `UrgentHelpButton` | 은행 담당자 연결 또는 승인된 긴급 채널 이동 | 고정 CTA |

고객에게 Case ID가 꼭 필요하면 Header의 보조 정보로만 제공하고, 위험점수·모델명·Version은 노출하지 않는다.

### 2.4 고객 채팅 필수 구성요소

- Customer Agent 일반 안내
- 즉시 안전 행동 카드
- P0 상황 확인 질문
- 선택지·예/아니요·자유답변
- 답변이 Case에 반영됐다는 확인
- 기관 검증 진행상태와 고객용 결과 요약
- 은행 담당자 메시지
- 담당자 Takeover·AI 상담 재개 안내
- 피해가 확인된 경우 피해구제 절차
- 파일·사진·문자 캡처 첨부
- 실패·재시도·연결 복구 안내

### 2.5 고객 화면에서 제외

- ML 위험점수와 Window 분석 결과
- FDS 원본·내부 거래 분석
- 은행 내부 메모
- 내부 AI 업무 대화
- 전체 Case Event Log
- RAG 검색점수·Chunk Metadata
- 보고서 Section Version
- 은행의 조치 초안과 승인 전 판단

## 3. 은행 화면

### 3.1 화면의 역할

은행 화면은 다음 업무에 집중한다.

1. 현재까지 확인된 사건 사실과 미확인사항을 파악한다.
2. Bank Copilot의 도움을 받아 고객 질문과 대응전략을 준비한다.
3. 고객·기관과 확인한 결과를 Case에 반영한다.
4. 은행 조치와 사건 진행 이력을 누락 없이 기록한다.

### 3.2 최종 Layout

```text
┌───────────────────────────────────────────────────────────────┐
│ Case Header: 상태 · 담당자 · 고객 연결 · 긴급 Action          │
│ 참여자: 채팅 담당 김OO · 검토 이OO · 보고 중 3명              │
├────────────────────────────────────────┬──────────────────────┤
│ Chat Workspace                         │ Case Live Log        │
│                                        │                      │
│ [AI 업무 대화] [고객 대화]             │ 10:42 고객 답변       │
│                                        │ 10:43 Case 갱신       │
│ · Bank Copilot 답변                    │ 10:44 검증 요청       │
│ · 질문 추천·승인                       │ 10:46 은행 조치 기록   │
│ · 고객 응답                            │                      │
│ · 검증 요청·결과                       │ Filter / Detail       │
│ · 조치 카드                            │                      │
│                                        │                      │
│ ┌────────────────────────────────────┐ │                      │
│ │ 현재 채널 · 첨부 · 입력 · 전송    │ │                      │
│ └────────────────────────────────────┘ │                      │
└────────────────────────────────────────┴──────────────────────┘
```

은행 화면에는 상시 LIVE Report Panel을 두지 않는다. 대신 `Case Live Log`를 통해 어떤 입력·검증·조치·상태 변경이 발생했는지 실시간으로 확인한다.

현재 Case의 구조화된 요약이 필요할 때는 다음 방식으로 연다.

- Header의 `현재 Case 요약` 버튼
- Case Update Card의 `변경 후 상태 보기`
- Drawer에서 확인된 사실·미확인사항·현재 조치 조회
- 사건 종료 시 FINAL 결과 카드

### 3.3 채팅 밖 필수 구성요소

| 구성요소 | 역할 | 표시 범위 |
|---|---|---|
| `BankCaseHeader` | Case 상태·Mode·담당자·고객 연결 상태 | 한 줄 Header |
| `ParticipantPresenceBar` | 채팅 담당자·Case 담당자·검토자·현재 보고 있는 인원 | Header 하단 한 줄 |
| `PriorityActionBar` | 즉시 검토해야 할 조치 또는 미확인 P0 | 있을 때만 표시 |
| `ConversationChannelTabs` | AI 내부 대화와 고객 대화 분리 | 항상 표시 |
| `CaseLiveLogPanel` | 저장된 Event를 시간순으로 확인 | 최근 Event 중심 |
| `ConnectionStatus` | Polling/SSE 연결과 마지막 반영 시각 | 보조 상태 |

### 3.4 은행 채팅 필수 구성요소

- Bank Copilot 일반 응답
- 현재 Case Brief 요청 결과
- 위험 근거·미확인사항 요약
- 고객의 새 답변
- 고객에게 보낼 질문 추천
- 질문 편집·승인·전송
- 기관 검증 질문 초안
- 기관 검증 요청·결과
- 공식문서 기반 대응 가이드
- 은행 조치 추천·기록·완료
- Human Takeover·Resume AI
- Case 변경 요약
- FINAL 결과 생성·확정
- Version Conflict·부분 실패·재시도

### 3.5 반드시 분리할 두 채널

#### AI 업무 대화

```text
은행 담당자 ↔ Bank Copilot
```

- 고객에게 노출하지 않는다.
- 위험 근거, 미확인사항, 질문 초안, 대응전략, 보고 결과를 다룬다.
- 기본 전송 대상은 `INTERNAL`이다.

#### 고객 대화

```text
은행 담당자 ↔ 고객
```

- 고객에게 실제로 전달되는 메시지만 포함한다.
- 질문 추천은 담당자가 승인·편집한 후 이 채널로 전송한다.
- 전송 버튼 주변에 `고객에게 전송` 대상을 명확하게 표시한다.

두 채널은 UI 상태뿐 아니라 Backend Message의 `audience` 또는 동등한 권한 필드로 분리해야 한다.

### 3.6 참여자 상태

은행 화면에는 참여자 전체 명단을 복잡한 표로 두지 않고 Header의 Avatar/이름 요약으로 제공한다.

```text
채팅 담당 김OO  ·  Case 담당 이OO  ·  검토 박OO  ·  보고 중 3명
```

- `채팅 담당`: 고객 채널로 실제 메시지를 보낼 담당자
- `Case 담당`: 상태 전환·조치 책임자
- `검토자`: 내부 검토 권한 보유자
- `보고 중`: 현재 Case Room을 보고 있는 사용자 수
- `입력 중`: 현재 채널에서 입력 중일 때만 짧게 표시

고객 화면에는 내부 참여자 이름과 역할을 노출하지 않고 `은행 담당자 확인 중` 또는 `담당자 상담 중`만 표시한다.

## 4. 공통 하단 입력창

### 4.1 기본 구성

```text
┌─────────────────────────────────────────────────────┐
│ 현재 대상: Customer Agent / Bank Copilot / 고객     │
│                                                     │
│ 메시지를 입력하세요                                 │
│                                                     │
│ [첨부] [빠른 요청]                    [전송]         │
└─────────────────────────────────────────────────────┘
```

### 4.2 공통 동작

- 채팅 Scroll 영역 안의 하단에 고정한다.
- 새 메시지가 생겨도 입력 중인 텍스트를 잃지 않는다.
- 전송 중에는 중복 요청을 막는다.
- `client_request_id`를 포함해 중복 저장을 방지한다.
- 실패하면 입력을 유지하고 재시도할 수 있게 한다.
- 첨부파일 전송 전 민감정보 주의문을 표시한다.
- 담당자 Takeover 상태에서는 고객의 AI 자동응답 여부를 명확하게 표시한다.

### 4.3 은행 입력창 추가 규칙

- 현재 채널과 수신 대상을 항상 표시한다.
- `AI에게 요청`과 `고객에게 전송`의 버튼 스타일을 다르게 한다.
- AI가 만든 고객 질문은 자동 전송하지 않고 담당자 검토를 거친다.
- 내부 메모와 고객 메시지를 같은 입력 동작으로 저장하지 않는다.

## 5. 반응형 우선순위

### Desktop

- 고객: Chat 70% + Progress 30%
- 은행: Chat 65~70% + Case Live Log 30~35%

### Tablet

- Chat 중심
- Progress/Log는 접을 수 있는 우측 Drawer

### Mobile

- Chat 전체 폭
- Header와 Safety/Action만 상단 고정
- Progress와 Case Log는 Bottom Sheet
- 입력창은 Safe Area를 고려해 하단 고정
