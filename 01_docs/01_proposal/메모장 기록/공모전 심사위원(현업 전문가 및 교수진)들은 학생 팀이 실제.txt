공모전 심사위원(현업 전문가 및 교수진)들은 학생 팀이 실제 은행 코어 망에 API를 연동하는 것은 불가능하다는 사실을 이미 잘 알고 있음.

따라서 이 심사기준에서 요구하는 ‘운영 계획’은 "실제 은행에 붙였다"가 아니라,
"실제 은행 전산 환경(보안/망분리/FDS)을 이해하고 있으며, 이를 고려한 현실적인 도입/통합 시나리오와 검증 방안을 준비했는가?"를 보여줘야 함.



학생 신분이라는 한계를 극복하고 심사위원에게 "현업 시스템의 생리를 제대로 이해하고 만든 기획"이라는 인상을 주기 위한 3단계 전략

1. 전산 연동의 한계를 극복하는 3가지 전략
① 가상 FDS 이벤트 에뮬레이터(Mock API) 구축
실제 은행 FDS 시스템에 연동할 수 없으므로, "은행 FDS에서 전송되는 위험 탐지 JSON 데이터"를 모의 생성하는 에뮬레이터를 직접 구현
웹 서비스 화면 한쪽에 FDS 위험 시뮬레이터 패널을 만들어 "지연 이체 발생 + 신규 기기 접속 + 악성 앱 감지" 같은 버튼을 누르면,
실제 은행 전산에서 들어오는 형태의 데이터가 웹 서비스 워크스페이스로 실시간 패싱되어 자동 대응 매뉴얼이 생성되는 과정을 시연

어필 포인트: 단순 UI 렌더링이 아니라 표준 REST API / Webhook 기반으로 설계하여 "실제 은행 FDS 연동 시 API 엔드포인트만 바꾸면 바로 동작하는 구조"임을 강조!!


② 온프레미스 / 폐쇄망(Air-Gapped) 배포 아키텍처 제시
금융권은 보안 정책상 외부 클라우드 LLM(OpenAI 등)으로 고객의 금융 거래 데이터를 전송하기 매우 까다로움
운영 계획서에 sLLM(소형 언어 모델, 예: Llama-3, Gemma4, Qwen 등)을 은행 내부 서버(On-Premise)에 로컬 배포하는 아키텍처를 다이어그램으로 제시...
지금은 프로토타입으로 OpenAI API를 사용했지만 이 후 적용해볼것임.


③ 사용자 역할(Role-based) 시나리오 제시
실제 은행의 [FDS 모니터링 담당자] → [지점 창구 창구 직원] → [소비자보호부 대응팀]으로 이어지는 실제 대응 프로세스를 정의하고,
서비스 내에서 권한별로 어떤 화면과 매뉴얼이 노출되는지 시나리오를 구성!



2. 공모전 제출 서류 [적합성: 기획·개발·운영 계획] 작성 가이드

[1] 시스템 아키텍처 및 연동 설계 (Integration Architecture)
표준 데이터 규격 정의: FDS 탐지 로그(거래 시간, 패턴, 악성 앱 감지 여부, 대화 정황 등)를 전달받는 Standard JSON Schema 설계

망 분리 및 보안 준수 구조:
1단계: 금융 데이터 비식별화 (이름, 계좌번호, 주민번호 패스워딩 처리)
2단계: 은행 내 사설 망(Private Network) 내 sLLM 기반 요약 및 매뉴얼 생성 engine 작동
3단계: 창구 직원용 모니터링 Dashboard(웹 워크스페이스)에 대응 매뉴얼 및 설득 스크립트 출력


[2] 개발 및 시뮬레이션 환경 (Development & Mock Environment)
Mock-up 데이터 기반 검증 계획: 실제 보이스피싱 피해 판례 및 금융감독원 피해 사례 데이터셋을 기반으로 총 50여 개의 가상 피싱 시나리오(대출 빙자형, 기관 사칭형 등) 구축

골든 타임(Golden Time) 대응 성능 목표 설정: FDS 이벤트 수신 후 매뉴얼 자동 생성까지 3초 이내 완료

행원이 30초 이내에 상황의 맥락(Context)을 파악할 수 있도록 핵심 요약 3줄 제공


[3] 단계별 운영 및 도입 로드맵 (Operation Roadmap)
Phase 1 (PoC / 현재 구현): Mock FDS 기반 프론트엔드/백엔드 웹 서비스 워크스페이스 구현 및 시나리오 테스트
Phase 2 (샌드박스 검증): 금융규제 샌드박스 또는 금융결제원 Open API 테스트베드를 활용한 모의 데이터 가상 테스트
Phase 3 (현장 적용 및 피드백): 은행 이상거래 대응팀 인터뷰 기반의 매뉴얼 유효성 평가 및 휴먼 에러(상황 오판, 대응 누락) 감소율 측정


3. 발표 및 시연 시 강조할 핵심 멘트
"저희 서비스는 은행의 기존 FDS 알고리즘을 바꾸는 것이 아니라, FDS 탐지 이후의 '골든타임 대응 프로세스'를 AI로 혁신하는 웹 워크스페이스입니다.
학생 신분의 한계로 실제 은행 DB에 직접 연결할 수는 없었으나,
금융권 표준 데이터 포맷 기반의 Mock API 환경을 구축하여 실제 은행 시스템 도입 시 즉시 Plug-and-Play가 가능한 구조로 개발 및 운영 계획을 수립했습니다.”
