## 1. 서비스 목표와 변경 불가 원칙

CSR(Case Share Room)은 보이스피싱 의심 사건에서 고객, 은행 직원, AI가 하나의 Shared Case를 통해 확인된 사실과 진행 업무를 공유하는 서비스다.

- AI는 은행 직원의 결정을 대신하지 않고 분석·추천·요약을 지원한다.
- 질문 응답, 안내 열람, AI 추론만으로 지급정지·피해구제·신고 등이 완료됐다고 표시하지 않는다.
- 고객 답변은 사실 후보이며, 담당자 또는 공식 기관이 확인한 사실과 구분한다.
- 고객 공개 내용과 은행 내부 기록을 분리한다.
- 통화 원문은 분석 중에만 사용하고 Shared Case에는 최소 핵심 피처와 집계 결과를 저장한다.
- `personal_info_shared`, `IMPERSONATION` 같은 내부 변수·코드명을 사용자 화면에 노출하지 않는다.
- 사건 맥락의 AI 생성본과 직원 편집본을 분리하며 직원 편집과 최종 결정권을 보호한다.
- Frontend는 AI API를 직접 호출하지 않고 General API를 단일 진입점으로 사용한다.

```text

  └─ /api → General FastAPI :8100
                ├─ MySQL / attachment storage
```

## 4. 아직 완료로 보면 안 되는 범위

- 사건 맥락 v2의 저장 리소스와 Frontend 업무 관리 화면을 연결했다. **실제 LLM projection 및 기존 고객 답변의 새 Fact/Gap 자동 이관은 아직 미연결**이다. 기존 사실 후보는 읽기 전용으로 보존하며 새 후보와 구분한다.
- 새 업무·사실·결정의 은행 AI/보고서 입력 연결은 완료했다. 기존 고객 답변의 새 리소스 영속 이관과 모든 Gap의 자동 동기화는 미완료이며, 이번에 자동 이관하지 않았다.
- 사건 맥락의 현재 요약은 **규칙 기반 재구성**이다. 실제 LLM 종합 재요약이 아니다.
- 사용자 표시 문구 점검에서 7개 문제군을 확인했으며 아직 미수정이다. VP-7 영어 사건 유형, 표시 사전/필드 누락, REPORT_CARD JSON 키 변형, 내보내기·오류 메시지 및 원문 보호 경계가 해당한다. `12_USER_TEXT_AUDIT.md`의 수정 순서와 근거를 우선 참조한다.
- 사건 기록 검색을 통한 RAG는 연결했다. **임베딩 기반 의미 검색은 아니다.** 한국어 문구·동의어 기반 검색으로, 완전히 다른 표현의 중복까지 보장하지 않는다. 구조화 상태 검사를 우선한다.
- 실제 인증 세션과 운영형 RBAC가 없다. 프론트의 고정 사용자와 요청 actor 값을 사용한다.
- 사건 관리 권한도 현재는 환경변수의 공용 관리자 암호 방식이며 사용자별 인증·감사 체계는 아니다.
- 변경 동기화는 5초 polling 중심이다. SSE/WebSocket은 없다.
- 자동 테스트는 통과하지만 실제 브라우저에서 전체 업무 흐름을 끝까지 수행하는 E2E 증거가 부족하다.
- AI 최종 결과 보고서의 실제 OpenAI 생성 품질은 운영 API 키로 별도 확인해야 한다. 자동 테스트는 계약·오류 처리·DB 저장 경로를 검증한다.
- 지급정지·신고·피해구제·기관 확인은 실제 외부 금융 시스템을 실행하지 않는다.
- 은행 북마크 일부와 고객 북마크는 브라우저 localStorage를 사용한다.
- 첨부파일 악성코드 검사, 오브젝트 스토리지, 서명 URL은 아직 없다.

## 5. 다음 작업 순서

> 아래는 장기 백로그도 포함한다. 이번 마감에는 위의 확정 범위를 우선하며 로그인·리팩터링·SSE·의미 임베딩 도입은 진행하지 않는다. 다음 즉시 작업은 실제 브라우저의 담당자 역할 선택 → 제안 채택/제외 → 채팅/질문 → 새로고침 유지 확인이다.

### P0-1. 실제 브라우저 전체 연동 검증

새 통화 분석부터 Case 생성, 은행·고객 채팅, AI 응답, 질문 카드, 사실 후보, 사건 맥락 갱신, 직원 편집과 새로고침 유지까지 하나의 시나리오로 검증한다. 말풍선이 늦게 나타나거나 사라지는 현상, 오래된 응답이 최신 UI를 덮는 현상을 집중 확인한다.

완료 조건:

- 정상·AI 장애 시나리오를 실제 화면에서 각각 통과
- 메시지가 먼저 표시되고 DB 저장 후 유지됨
- 새로고침 후 메시지·카드·직원 편집 상태가 동일함
- 질문 응답만으로 공식 처리 단계가 완료되지 않음
- 콘솔 오류와 예기치 않은 4xx/5xx가 없음

### P0-2. 최신 Shared Case 기반 실제 LLM 사건 맥락

`context_revision`이 바뀔 때만 최신 사실·질문·답변·기관 확인·업무 기록을 구조화해 LLM에 전달한다. 요약은 누적 연결문이 아니라 3~5개의 개조식 핵심 항목으로 재작성한다.

선행 기준: `09_CASE_CONTEXT_DATA_CONTRACT.md`의 Fact·Gap·AI Suggestion·Staff Task·Decision 분리 계약은 승인됐다. 개발 DB migration과 화면용 workspace를 연결했다. 다음은 기존 질문·답변·확정 사실의 안전한 동기화와 새 리소스를 포함하는 실제 AI projection 검증이다.

완료 조건:

- 동일 revision에서 LLM 중복 호출 없음
- 직원 편집본을 AI가 덮어쓰지 않음
- 실패 시 마지막 정상 projection 유지
- AI 결과와 규칙 기반 fallback이 명확히 구분됨
- 내부 코드명과 고객 비공개 데이터가 노출되지 않음

### P0-3. RAG 기반 중복 질문 방지

구조화 상태 검사를 먼저 수행하고, 표현만 다른 중복을 의미 검색으로 보완한다. 질문·답변·확정 사실·기관 확인 결과를 Case와 공개 범위 안에서만 검색한다.

완료 조건:

- 이미 답변됐거나 확정된 내용을 다시 질문하지 않음
- 검색 결과에 출처 ID·revision·확인 상태·공개 범위 포함
- 직원이 제외한 AI 체크리스트 항목이 자동 재생성되지 않음
- 검색 문장을 지시문이 아닌 데이터로만 취급함

### P0-4. 실제 인증과 서버 권한

고정 `CURRENT_BANK_USER`/`CURRENT_CUSTOMER_USER`와 요청 본문 actor 신뢰를 제거한다. 인증 세션에서 신원을 결정하고 Case 참여 역할에 따라 조회·편집·공개·참여자 관리 권한을 검사한다.

### P1-1. 고객 진행 상황과 AI 답변 일치

`확인 필요`, `접수`, `진행 중`, `완료`를 구분하고, AI가 확인된 상태와 고객의 다음 행동을 나누어 답하도록 한다. 내부에 있는 정보를 고객에게 다시 외부 문의하라고 안내하지 않는다.

### P1-2. SSE/WebSocket 기반 동기화

5초 polling을 Case 변경 이벤트 구독으로 교체한다. 입력 중인 텍스트와 모달 상태를 유지하고, 연결 장애 때만 저빈도 polling을 fallback으로 사용한다.

### P1-3. 직원 통제 기능 최종 QA

체크리스트 수정·완료·제외·복원, 사건 맥락 편집 이력, 동시 수정 409, 직원 편집 보호를 실제 MySQL과 브라우저에서 검증한다.

### P1-4. DB와 사용자 표시 경고 정리

- 사용자 표시 점검 상세: `12_USER_TEXT_AUDIT.md`. 용어 사전 확대 전에 REPORT_CARD JSON의 키·ID를 보호해야 한다(U-01).
- `risk_score` 저장 단위를 0~1 또는 0~100 중 하나로 확정하고 DECIMAL 정밀도 경고 제거
- MySQL의 폐기 예정 `VALUES()` upsert 구문 교체
- 오류·fallback·질문·사건 맥락·내보내기 경로의 내부 코드명 노출 전수 검사

### P2. 운영형 기능

- 북마크와 사용자 설정의 서버 영속화
- 첨부파일 악성코드 검사·오브젝트 스토리지·서명 URL
- 외부 금융·기관 시스템 연동과 직원 승인·감사·재시도
- AI quota, 모델·프롬프트 버전, 관측성과 장애 복구
- 부하·보안·접근성·모바일·시각 회귀 테스트

## 7. 작업 운영 규칙

1. 모든 작업은 이 문서의 서비스 원칙과 현재 미완료 경계를 먼저 확인한다.
2. 작업 시작 시 실제 코드·DB 계약·테스트를 대조해 문서가 오래됐는지 확인한다.
3. 변경은 가능한 한 위의 P0 → P1 → P2 순서로 진행한다.
4. 구현 후 관련 단위·계약·프론트 빌드를 실행한다.
5. 실제 검증을 하지 않은 기능은 완료로 표시하지 않는다.
6. 작업 종료 시 이 문서의 완료 범위, 다음 작업, 테스트 수치와 남은 경고를 갱신한다.
7. 세부 체크 항목이나 과거 결정 근거가 필요할 때만 `02_DETAILED_TODO.md`와 관련 설계 문서를 함께 참조한다.
