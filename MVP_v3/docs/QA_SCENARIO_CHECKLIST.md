보이스피싱 의심 사건의 생성부터 담당자 협업, AI 분석, 고객 공유, 종결·복구까지 전체 서비스 흐름을 수동 점검하기 위한 문서입니다.

## 1. 새 통화 분석과 Case 생성

### QA-001 정상적인 보이스피싱 원문 분석

입력 예시:

```text
서울지검 수사관입니다.
고객님 명의 계좌가 범죄에 연루됐습니다.
오늘 안에 안전계좌로 자금을 이체해야 합니다.
수사 중이므로 가족이나 은행 직원에게 알리지 마세요.
통화를 끊지 말고 지금 바로 이체 절차를 진행해 주세요.
```

- [ ] `새 통화 분석하기` 화면이 열린다.
- [ ] 분석 중 다른 이동·서비스 버튼이 비활성화된다.
- [ ] 분석 완료 후 결과 화면이 표시된다.
- [ ] `보이스피싱 의심 인물`과 고객 역할이 구분된다.
- [ ] `서울지검`, 계좌 범죄 연루, 안전계좌, 송금 요구, 외부 연락 제한, 긴급성이 추출된다.
- [ ] 원문 전체가 DB에 저장되지 않는다.
- [ ] `추가 구조화 정보`에서 원문 세부 요소를 확인할 수 있다.
- [ ] 생성된 Case를 열 수 있다.

결과/메모:

### QA-002 긴 원문·반복 금액 분석

- [ ] 긴 입력을 넣어도 무한 대기나 브라우저 멈춤이 발생하지 않는다.
- [ ] 동일 금액을 여러 차례 송금한 내용이 한 건으로 뭉개지지 않는다.
- [ ] 요구 금액·실제 이체 금액·추가 이체가 구분된다.
- [ ] 분석 한도에 도달해도 가능한 범위의 부분 결과가 반환된다.
- [ ] JSON 파싱 오류 전문이 사용자 화면에 노출되지 않는다.

결과/메모:

### QA-003 모호하거나 사기성이 낮은 입력

- [ ] 송금 요구가 없는 입력에서 사기 정황이 과도하게 생성되지 않는다.
- [ ] 확인되지 않은 내용이 확정 사실로 표시되지 않는다.
- [ ] 위험도·근거·확인 필요 상태가 서로 일관된다.

결과/메모:

### QA-004 분석 결과 문장 품질

- [ ] 주체가 뒤바뀌지 않는다.
- [ ] 요청자·피해자·사칭 대상이 구분된다.
- [ ] 금액·행동·시간이 자연스럽게 연결된다.
- [ ] 원문에 없는 사실이 요약에 추가되지 않는다.
- [ ] 전체 요약과 세부 카드의 내용이 서로 모순되지 않는다.

## 2. 최초 Case 진입과 담당자 배정

### QA-005 최초 담당자 배정

- [ ] 새 Case 최초 진입 시 담당자 배정 창이 열린다.
- [ ] 현재 사용자 `나`가 기본 담당자로 포함된다.
- [ ] 담당자가 최소 1명 이상 배정되어야 Case Room이 열린다.
- [ ] 담당자 저장 전 상세 Case가 열리지 않는다.
- [ ] 담당자 저장 후 상세 Case가 정상적으로 열린다.
- [ ] 새로고침 후 최초 배정 창이 반복해서 열리지 않는다.

결과/메모:

### QA-006 담당자 추천 배정

- [ ] `담당자 추천 배정 받기` 버튼이 표시된다.
- [ ] FDS·상담·사건 총괄 후보가 역할에 맞게 추천된다.
- [ ] 기존 담당자가 제거되지 않는다.
- [ ] 같은 역할이 불필요하게 중복 배정되지 않는다.
- [ ] 배정 불가 상태의 직원이 추천되지 않는다.
- [ ] 추천 결과를 저장 전에 직접 수정할 수 있다.

결과/메모:

### QA-007 담당자 편집

- [ ] 담당자 추가가 동작한다.
- [ ] 담당자 제거가 동작한다.
- [ ] 배정 역할 변경이 저장된다.
- [ ] 사건 총괄은 항상 정확히 1명이다.
- [ ] 현재 사용자를 제거할 수 없다.
- [ ] 저장 실패 시 서버 상태를 다시 불러온다.

결과/메모:

- [ ] 사용자가 자동 설정을 직접 변경할 수 있다.

- [ ] 첨부파일 추가가 동작한다.
- [ ] 고객에게 질문하기 버튼이 동작한다.
- [ ] 고객 공개 메시지와 내부 메시지가 구분된다.

결과/메모:

### QA-011 은행 내부 소통용 채팅

- [ ] 은행 내부 소통용 채널이 표시된다.
- [ ] `conversation-channel-toggle`이 헤더 오른쪽에 있다.
- [ ] 내부 메시지가 고객 화면에 노출되지 않는다.
- [ ] AI 답변 요청이 동작한다.

### QA-012 채팅 분할과 반응형 레이아웃

- [ ] 고객 또는 내부 채팅 접기 상태가 정상이다.
- [ ] 우측 사건 패널을 접어도 채팅 분할 손잡이는 유지된다.

## 5. 사건 정보 패널

### QA-013 사건 정보 패널 열기·닫기

- [ ] 우측 패널 안에 토글 버튼이 있다.
- [ ] 헤더에 별도의 우측 패널 토글 버튼이 없다.
- [ ] 패널을 닫으면 40px 얇은 패널만 남는다.
- [ ] 얇은 패널 안에 열기 버튼이 표시된다.
- [ ] 열기 버튼을 누르면 패널이 다시 확장된다.
- [ ] 접힘 상태에서 채팅 분할 손잡이는 유지된다.

결과/메모:

### QA-014 사건 정보 패널 너비 조절

- [ ] `context-resize-handle`을 드래그해 너비를 조절할 수 있다.
- [ ] PC 화면에서 너비 조절이 동작한다.
- [ ] 좁은 화면에서도 최소 너비까지 줄일 수 있다.
- [ ] 패널 접힘 상태에서는 `context-resize-handle`이 사라진다.
- [ ] 패널 헤더가 흰색으로 표시된다.
- [ ] 헤더 문구가 `사건 정보 / 사건 현황`으로 표시된다.

결과/메모:

### QA-015 Context 섹션 표시

- [ ] 현재 사건 요약
- [ ] 피해·노출

- [ ] 분류 대기 관찰

## 6. Context V3 상태와 업무

### QA-016 Fact 추출·검토·확정

- [ ] 채팅 저장 후 구조화 Fact 후보가 생성된다.
- [ ] 후보 Fact는 확인 필요 상태로 표시된다.
- [ ] `확인하기`로 Fact를 확정할 수 있다.
- [ ] 확정 Fact에 근거·시각이 표시된다.
- [ ] 확정 내용이 Context 요약에 반영된다.
- [ ] 직원 편집·확정 내용이 AI 자동 갱신으로 덮어써지지 않는다.

### QA-017 Fact 기각·정정

- [ ] 확정 Fact를 기각할 수 있다.
- [ ] 기각 후 최신 요약에서 해당 내용이 빠진다.
- [ ] 정정 Fact를 새 제안으로 만들 수 있다.
- [ ] 기존 Fact 이력이 보존된다.
- [ ] 동일 Fact가 중복으로 누적되지 않는다.

## 7. 고객 질문과 고객 화면

### QA-019 고객 질문 생성·전송

- [ ] 고객에게 질문하기 창이 열린다.
- [ ] AI 추천 질문이 표시된다.
- [ ] 중복 질문이 과도하게 생성되지 않는다.
- [ ] 질문을 수정·삭제·선택할 수 있다.
- [ ] 질문 전송 후 고객 채팅에 표시된다.
- [ ] 질문 상태가 대기 상태로 저장된다.

결과/메모:

### QA-020 고객 답변 반영

- [ ] 고객 화면에서 질문을 확인할 수 있다.
- [ ] 고객이 답변할 수 있다.
- [ ] 은행 화면에 답변이 반영된다.
- [ ] 답변이 Fact 후보로 변환된다.
- [ ] 답변 내용이 바로 확정 사실로 처리되지 않는다.

결과/메모:

### QA-021 고객 화면 공개 범위

- [ ] 고객 화면에 진행 상태가 표시된다.
- [ ] 고객 화면에 내부 채팅이 노출되지 않는다.
- [ ] 직원 메모·내부 판단·민감 계좌·연락처가 노출되지 않는다.
- [ ] 은행이 공개한 처리 결과만 표시된다.

결과/메모:

### QA-022 고객 진행 상태
