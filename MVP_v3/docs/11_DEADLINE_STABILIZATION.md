# 마감용 안정화 범위와 확인 방법

기준일: 2026-09-05. 작업 시작 시 `03_IMPLEMENTATION_STATUS.md`를 먼저 읽는다.

## 이번 범위

Frontend, General FastAPI(8100), AI FastAPI(8101), MySQL, 사건별 RAG 연결을 안정화한다.
새 로그인/인증 체계, 대규모 리팩터링, SSE/WebSocket, 벡터 DB 추가는 제외한다.
기존 데이터는 자동 이관하거나 삭제하지 않는다. 기존 고객 진술과 새 사실/업무는 구분해서 보존한다.

## 화면 사용

1. 사건을 연 뒤 `참여자 관리 → 내 역할을 검토자로 설정`을 누른다.
2. 이 명시적 설정 뒤 AI 업무 제안의 `수정·채택`, `제외`, 사실 확정, 업무 결과 기록을 사용할 수 있다.
3. 역할 변경은 즉시 사건 맥락 버튼에 반영한다. 메인 담당자/다른 관계자를 자동으로 바꾸지 않는다.
4. 채택은 담당자 업무 생성일 뿐 고객 질문 발송이나 실제 지급정지 완료가 아니다.
5. 고객에게 보여 줄 공식 처리 상태는 `고객에게 공유할 처리 결과`에서 별도로 확인 후 기록한다.

## RAG 구현 범위

- General API가 DB에서 해당 사건 자료를 읽고, 관련 기록을 검색해 기존 AI 호출의 입력에 추가한다.
- 한국어 문자 2/3-gram TF-IDF·cosine 유사도와 제한적인 동의어 정규화를 사용한다. 별도 설치/유료 임베딩 호출이 없다.
- 이는 **문구 기반 검색 RAG**이며 임베딩 의미 검색, 외부 금융 지식 검색, 첨부 원문 검색이 아니다.
- 사실·질문/답변의 구조화 상태가 우선이다. 검색 점수만으로 사실을 확정하거나 금융 업무를 완료하지 않는다.
- 같은 사건·같은 공개 범위만 인덱싱한다. 고객 검색에 내부 업무/판단, 개인 AI 대화, 아직 발송하지 않은 질문을 넣지 않는다.
- 이전 AI 응답/보고서 카드는 독립적인 증거로 재사용하지 않는다.
- 수정/제외/정정 후 실제 내용 지문이 바뀌면 다음 검색에서 캐시를 교체한다. 출처 없는 불완전 레코드는 검색 근거에서 제외한다.
- 인덱스 최대 32개, 사건 입력 최대 2,000개 기록, 검색 결과 최대 6건·각 750자. 매우 큰 사건의 전 기록 무제한 검색을 보장하지 않는다.
- 최신 직원 사실·업무·결정은 질의와의 문구 유사성과 별도로 제한된 필수 맥락에 포함한다. 고객에게는 비공개다.
- 검색 결과는 지시가 아닌 데이터로 취급하고 최신 확정 사실/처리 상태를 과거 진술보다 우선하도록 AI에 지시한다.
- 질문 중복 방지는 구조화 target field 검사 + 보수적인 문구 유사도 검사다. 완전히 다른 표현의 중복을 모두 판별하는 의미 모델은 후속 범위다.

AI 입력에 관련 근거를 추가하는 방식은 [OpenAI 공식 프롬프트 지침](https://developers.openai.com/api/docs/guides/prompt-engineering)에 따라 연결했다. 모델 자체는 변경하지 않았다.

## 검증 결과

- General API 132개 통과 (MySQL 격리 스키마 검사 포함)
- AI API 89개 통과
- Frontend typecheck/build 통과, 회귀 스크립트 34개 통과
- 5176 / 8100 health / 8101 health 모두 HTTP 200
- 실제 VP-6 DB 기록 4건 검색 → 실제 gpt-4o-mini 응답 1회 성공
- 위 실제 AI 검사: 재시도 0, 동시 호출 1, 사건/메시지 저장 0
- Browser 연결 가능한 인스턴스가 없어 실제 클릭 E2E는 미수행

읽기 전용 검증 재실행 (PowerShell, MVP_v3에서):

```powershell
$env:PYTHONPATH='backend'
.\.venv\Scripts\python.exe backend/scripts/smoke_case_rag.py --case-id VP-6
```

`--live-ai`를 추가하면 실제 유료 응답 1회를 호출한다. 기본값은 AI 미호출이다.
이 스크립트는 DB/기록 검색과 AI 연결을 검사하며 General API의 메시지 저장 경로 또는 브라우저 클릭 검증을 대신하지 않는다.

## 남은 최소 수동 QA

- 참여자 역할 선택 후 `수정·채택/제외 → 저장 → 새로고침` 결과 유지
- 은행 @AI / 고객 메시지 즉시 표시 후 답변 도착, 같은 말풍선 중복/소실 없음
- 질문 회신 후 같은 내용 재질문 없음, 회신과 공식 처리 완료를 혼동하지 않음
- AI 연결 실패 시 실제 오류 안내, 가짜 응답 없음
- 종결 보고서 카드와 PDF/Word 다운로드 확인

## 의도적으로 이번에 끝내지 않은 것

사건 맥락 요약은 기존 규칙 기반 개조식 투영을 유지한다. 전체 LLM 재요약, 기존 고객 답변의 새 Fact/Gap 자동 이관, 무제한 전 기록 처리, 운영용 권한/인증은 완료로 표시하지 않는다. 로그인 없는 상태이므로 외부 공개 운영 환경으로 배포하지 않는다.
