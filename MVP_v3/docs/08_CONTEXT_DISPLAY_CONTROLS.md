# 사건 맥락 개조식 표시 및 직원 제어

## 이번 반영

- 규칙 기반 사건 요약은 긴 최초 요약을 다시 붙이지 않고 사건 유형·핵심 주장, 현재 고객 상태, 현재 업무, 다음 확인을 최대 네 줄로 재구성한다. 업무 전체 목록은 요약에 누적하지 않는다.
- 요약은 기본 네 항목, 나머지 설명 영역은 세 항목을 노출한다. 긴 항목은 기본 화면에서 짧게 표시하고 전체 보기로 원래 설명을 확인할 수 있다. 목록 중복 문장을 제거한다.
- 요약·신호·상대방 주장·요구·수법·피해 노출 설명·다음 업무 제안에 연필/숨김/복원/직원 수정 해제 버튼을 제공한다. 한 줄에 한 항목을 입력해 항목을 추가하거나 제거할 수 있다.
- 수정은 표시용 overlay이며 CaseFact 확정, 실제 피해 상태, 기관 검증, 금융 업무 완료를 변경하지 않는다. 직원 원안은 자동 갱신에 덮어쓰지 않고 삭제 표시도 유지한다. 수정 해제는 최신 자동 표시로 돌아간다.
- 기존 012 테이블과 감사 이력을 사용한다. section/display 의미 키로 저장하며 Case 행 잠금과 expected_version으로 최초 삽입·수정을 직렬화한다. 직원 편집 자체는 LLM 호출을 유발하지 않는다.
- 기존 내용 캐시를 새 규칙으로 재생성할 수 있도록 projection 스키마 버전을 case-support.v2로 변경했다. 재생성 실패 시 마지막 성공본을 유지한다.
- 프론트 공통 응답 표시 계층에서 알려진 피처 코드를 한국어로 바꾼다. 매핑이 없는 snake_case 식별자는 설명 영역에서 추가 확인 정보로 표시한다. 식별자 필드·라우팅·API 키·URL·파일명·원본 사용자 메시지는 보존한다. 기존 북마크에도 읽기 시 표시 변환을 적용한다.
- 전체 기록의 이벤트명과 알 수 없는 업무/검증 상태의 코드 fallback을 한국어로 교체했다. P0/P1/P2는 긴급/우선 확인/일반 확인으로 표시한다. 실제 AI 대화 생성 결과에서도 알려진 내부 필드명은 저장 전에 한국어로 치환한다.

## 사용

은행의 사건 맥락에서 연필을 누른 뒤 한 줄씩 추가/수정하고 저장한다. X는 영역 숨김이다. 숨긴 영역 제목의 복원 버튼으로 다시 연다. 직원 수정 해제를 선택하면 현재 자동 내용이 표시된다. 다른 직원이 먼저 저장했으면 409를 표시하고 현재 작성 중인 내용을 보존한다. 취소 후 최신 버전으로 편집을 다시 열 수 있다.

표시 편집은 기존 MVP 사용자 ID로 사건 멤버의 담당자·검토자 역할을 확인한다. 클라이언트가 보내는 사용자 ID 자체는 인증 수단이 아니므로, 이 기능이 운영용 로그인·인증 체계를 완성한 것은 아니다. 현재 서버의 회원 등록/역할 변경 구조와 같은 신뢰 모델이다.

## 범위와 다음 단계

실제 LLM 재요약과 RAG 유사 질문 검색은 이번 변경에 포함하지 않았다. 최신 질문·답변·확정 사실의 구조 검사를 우선하고, 표현만 다른 중복을 찾는 검색 계층은 별도 작업으로 남아 있다. 현재 요약은 규칙 기반 재구성이며 LLM 재작성 결과로 표시하지 않는다.

체크리스트의 진행/완료 기능은 기존 Action API를 사용한다. 이번 화면 편집은 설명 섹션 단위이며 Action 자체의 제목 수정·삭제 이력 UI를 추가한 것은 아니다.

## 검증

직원 수정·숨김·복원·자동 표시 복귀, 버전 충돌, 사건 역할 범위, 실제 사실/업무 불변, 긴 요약 재누적 방지와 기존 관련 백엔드 회귀 테스트를 실행한다. 프론트는 test-context-display.cjs의 코드명 변환·ID 및 URL 보존·원본 사용자 메시지 보존·네 항목 렌더링과 빌드를 검사한다. 브라우저 실클릭과 실제 MySQL/LLM 연동 검증은 별도다.
