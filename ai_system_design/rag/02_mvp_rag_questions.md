# CONTEXT-FIRST CASE — MVP RAG Representative Questions

## 1. 목적

이 문서는 MVP Corpus 범위와 Retrieval 테스트 범위를 빠르게 정하기 위한 대표 RAG 질문 세트다. 모든 RAG 가능성을 다루지 않으며, 대표 질문으로 최소한의 공식 Knowledge 조사 대상을 정한다. RAG는 담당자의 판단을 지원할 뿐 최종 보이스피싱 판정이나 금융 조치를 수행하지 않는다.

## 2. 대표 질문 선정 원칙

- Case Evidence만으로 답할 수 없고 외부 공식 Knowledge가 필요한가?
- 정부·공공기관 또는 해당 기관의 공식자료로 검증 가능한가?
- MVP Case 대응에서 중요하며, Retriever의 성공·실패를 명확히 평가할 수 있는가?
- 다른 질문과 중복되지 않고 하나의 조사 범위로 관리 가능한가?

## 3. MVP 대표 질문

### Q01. 수사기관·금융당국 또는 금융회사가 자산 보호를 이유로 특정 계좌로 송금하도록 요구하는 공식 절차가 있는가?

업무 목적: VERIFICATION

왜 RAG가 필요한가: 상대방의 기관 사칭 주장과 실제 공식 절차를 비교하려면 Case 내부 Evidence 밖의 공식 근거가 필요하다.

필요한 공식 Knowledge:

- 수사기관의 공식 대국민 안내 및 사칭 주의 안내
- 금융당국·금융회사의 공식 고객 안내 및 사칭 대응 기준

예상 공식 출처 유형: 경찰청, 검찰청, 금융위원회, 금융감독원, 금융회사 공식 안내

주의: 아직 실제 출처 URL이나 기관별 절차 내용을 확정하지 않는다.

### Q02. 상대방이 실제 경찰·검찰·금융기관인지 어떤 공식 방법으로 확인해야 하는가?

업무 목적: VERIFICATION

왜 RAG가 필요한가: 공식 확인 채널과 검증 원칙은 Case Evidence가 아니라 각 기관의 공식 안내로 확인해야 한다.

필요한 공식 Knowledge:

- 기관 사칭 여부의 공식 확인 방법
- 공식 웹사이트·대표 채널 확인 시 유의사항

예상 공식 출처 유형: 경찰청, 검찰청, 금융감독원, 금융회사 공식 안내

주의: 아직 실제 연락처·URL이나 확인 절차를 확정하지 않는다.

### Q03. 고객이 실제로 송금한 상태라면, 지급정지와 관련해 어떤 공식 절차를 확인해야 하는가?

업무 목적: RECOVERY

왜 RAG가 필요한가: 실제 금전 이동 이후의 대응은 공식 절차·제도 안내가 필요하며, 상대방의 송금 요구만으로 이 질문을 적용할 수는 없다.

필요한 공식 Knowledge:

- 피해 발생 직후 금융 대응 관련 공식 안내
- 지급정지 관련 공식 절차 안내

예상 공식 출처 유형: 금융위원회, 금융감독원, 금융회사, 경찰청

주의: `TRANSFER_REQUEST`와 실제 `TRANSFER_COMPLETED`를 구분하며, 요건·가능 기간·권한은 아직 확정하지 않는다.

### Q04. 보이스피싱 피해 또는 의심 상황에서 어떤 공식 신고 절차를 확인해야 하는가?

업무 목적: REPORTING

왜 RAG가 필요한가: 신고 대상과 절차는 기관의 공식 안내를 근거로 해야 하며 Case 요약만으로 답할 수 없다.

필요한 공식 Knowledge:

- 보이스피싱 의심·피해 신고 관련 공식 안내
- 사건 접수 전 확인·준비 사항

예상 공식 출처 유형: 경찰청, 검찰청, 금융감독원, 정부·공공기관 공식 안내

주의: 실제 신고 세부 절차나 처리 기한은 아직 확정하지 않는다.

### Q05. 실제 금전 피해가 발생한 경우 어떤 공식 피해구제 절차를 확인해야 하는가?

업무 목적: RECOVERY

왜 RAG가 필요한가: 피해구제의 존재와 확인 경로는 외부 공식 제도 Knowledge가 필요하고, 단순 송금 요구와 실제 피해 발생을 구분해야 한다.

필요한 공식 Knowledge:

- 보이스피싱 피해구제 제도 공식 안내
- 신청·확인에 필요한 공식 기준 안내

예상 공식 출처 유형: 금융위원회, 금융감독원, 금융회사, 법령·공식 제도 안내

주의: 적용 조건·법적 효력·처리 기한은 공식자료 조사 전 확정하지 않는다.

### Q06. 악성앱 또는 원격제어 앱 설치를 요구받았거나 실제 설치한 경우 어떤 공식 대응을 확인해야 하는가?

업무 목적: SECURITY

왜 RAG가 필요한가: 앱 설치 요구와 실제 설치는 다른 상태이며, 각 상태에 필요한 공식 보안 대응 지식은 외부 출처가 필요하다.

필요한 공식 Knowledge:

- 악성앱·원격제어 관련 공식 보안 안내
- 실제 설치 또는 의심 상태에서의 공식 대응 안내

예상 공식 출처 유형: KISA, 과학기술정보통신부, 금융감독원, 금융회사 공식 안내

주의: `APP_INSTALLATION_REQUEST`와 `APP_INSTALLED`를 구분하며, 현재 Case의 실제 설치 여부를 RAG가 결정하지 않는다.

### Q07. OTP·인증번호·비밀번호를 요구받았거나 실제 노출한 경우 어떤 공식 대응을 확인해야 하는가?

업무 목적: SECURITY

왜 RAG가 필요한가: 인증정보 요구와 실제 노출은 구분해야 하며, 금융·보안 기관의 공식 대응 안내가 필요하다.

필요한 공식 Knowledge:

- 인증정보·계정정보 노출 관련 공식 보안 안내
- 금융보안 복구 및 추가 피해 방지 관련 공식 안내

예상 공식 출처 유형: 금융감독원, 금융보안원, KISA, 금융회사 공식 안내

주의: `CREDENTIAL_REQUEST`와 `CREDENTIAL_EXPOSURE`를 구분하며, 요구 사실만으로 노출 완료로 처리하지 않는다.

### Q08. 신고나 피해구제를 위해 어떤 기록과 Evidence를 보존해야 하는가?

업무 목적: REPORTING

왜 RAG가 필요한가: 보존 대상과 제출·확인에 필요한 자료는 기관별 공식 안내를 확인해야 한다.

필요한 공식 Knowledge:

- 신고·피해구제 관련 증거 및 기록 보존 안내
- 거래·메시지·앱 관련 자료의 공식 확인 필요 사항

예상 공식 출처 유형: 경찰청, 금융감독원, 금융회사, 정부·공공기관 공식 안내

주의: 현재 Evidence의 배열이나 문장 번호를 실제 통화 시점·순서로 추정하지 않는다.

## 4. RAG를 사용하지 않아도 되는 대표 요청

- 현재 사건 핵심을 정리해줘 — 현재 Case Evidence와 Structured Case Facts만으로 우선 처리할 수 있다.
- 위험 근거와 반대 근거를 정리해줘 — 내부 Evidence의 구조화·비교가 중심이다.
- 현재 Case Evidence에 있는 금액·주장·요구를 추출해줘 — 외부 공식 Knowledge가 필수적이지 않다.
- 아직 확인되지 않은 정보를 알려줘 — 현재 Case의 미해결 Facts를 기준으로 정리할 수 있다.

## 5. 다음 공식자료 조사 우선순위

1. 기관 사칭과 특정 계좌 송금 요구 관련 공식 절차·확인 방법
2. 실제 송금 이후 지급정지 및 피해 발생 직후 금융 대응
3. 보이스피싱 신고 및 피해구제 공식 안내
4. 악성앱·원격제어·인증정보 노출 관련 공식 보안 대응
5. 신고·피해구제를 위한 증거·기록 보존 안내
